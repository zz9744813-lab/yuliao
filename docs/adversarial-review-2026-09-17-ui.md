# 盲评控制台 · 视觉质感升级 + 差异高亮 — 对抗性自审查

日期：2026-09-17
范围：`app/static/index.html`（重写）、新增 `app/static/diff.js`、新增 `tests/test_diff_js.py`
动机：集霸判定 2026-09-16 的 UI 优化"效果不够好"，要求参考成熟项目重做视觉质感。
方向由 AskUserQuestion 定：**只做视觉质感**（不做预取队列/顺序揭示/swipe），
差异高亮做成**开关**（默认关），阅读视图保持**桌面并排两栏**。

## 研究输入（成熟项目，只取设计思想，不引代码/CDN）

| 项目 | 采取的做法 |
|---|---|
| Label Studio | 令牌两层结构（原语→语义→`data-theme` 换肤）；设置收进齿轮下拉（settings 表模式：key/label/kind/apply） |
| Chatbot Arena | 判定按钮的即时反馈节奏（已沿用：picked 描边 + 缩放） |
| Argilla | 完成态的多状态呈现（done-panel 的 ✦/⚠ 双形态） |
| diff-match-patch / jsdiff | `cleanupSemantic` 的思想 → 自写"小空隙桥接"（≤2 字的相同片段并入相邻改动） |

**不引外部依赖**的理由：控制台通过公网隧道暴露，2026-09-16 审计已标出外部暴露风险。
diff.js 是自写的 ~200 行 LCS（含 DP 单元数封顶），MIT 无忧，且测试可覆盖。

## 变更清单

### A 地基：令牌两层 + 深色模式
- `:root` 原语层（`--n-0..950` 中性色阶、`--acc-*` 棕金）→ 语义层（`--bg/--surface/--line/--fg/...`）；
  组件**只引用语义令牌**。`html[data-theme="dark"]` 只重映射语义层。
- 原来散落在组件里的硬编码色全部令牌化：toast、chip.up/dis/nov、改判横幅、kbd、
  A/B 卡片顶条与胜出描边、tag 状态边、上文颜色、滚动条。
- **夜读模式**：非纯黑（`#131316` 底 / `#1c1c20` 卡面）；批注 7 色 k0–k6 全部出暗色版
  （`rgba` 底 + 提亮的下划线），并单独定义了深色下 A/B badge 的描边版。
  首次访问跟随 `prefers-color-scheme`，`<head>` 内联脚本在首次绘制前就定主题（**无浅→深闪烁**）。
- 齿轮下拉（`#rv-settings`）：主题 / 密度（舒适 20px·2.05 / 紧凑 14px·1.85）/ 字号。
  全部 localStorage 持久化（`rv_theme`/`rv_density`/`rv_font`）。点页面外部自动关闭。

### B 排版与质感
- 中文排版：`hanging-punctuation: allow-start`（正文 + 上文）、`text-wrap: pretty`、
  正文栏 `max-width: 34em`（移动端解除）、行距走 `--rv-line`。
- A/B 栏头 sticky（长段滚动时标签始终可见）；主题化细滚动条（`scrollbar-width: thin`
  + webkit thumb，hover 加深）；卡片/弹层/dock 三级阴影令牌（`--shadow-sm/md/dock`）。
- `:focus-visible` 焦点环；按钮 180ms 微动 + 压下位移；toast 滑入淡入（双 rAF 确保
  `display→block` 的过渡能播）；完成态 ✦、错误态 ⚠；空态左侧细条。
- `prefers-reduced-motion` 下禁用动画（无障碍）。
- **切题骨架屏**：`showSkeleton()` 在 fetch 期间渲染 3 行 shimmer 占位，不再白屏闪填字。

### C 差异高亮（默认关，工具栏"差异：关/开"按钮）
- `app/static/diff.js`（自写、零依赖）：
  - `diffChars(a,b)` — 字符级 LCS（`Uint16Array` DP，单元数封顶 4e6，超长退化）；
  - `highlightSpans(a,b)` — 返回两侧**绝对偏移**区间：A 侧 `del`（被改掉的）/ B 侧 `ins`（新写的），
    带 `mergeNear(≤2)` 桥接（避免中文逐字 diff 满屏单字红绿）；
  - `composeHtml(text, marks, spans, kinds)` — 把 diff 高亮与噪点 mark 按位置复合渲染。
- **偏移契约（本次最核心的约束）**：composer 只产**内联**标签（`<i class="dhl">`、`<mark>`），
  剥标签后与原文逐字相等 → `offsetOf()` 的 textContent 对齐**完全不变**，划选批注直接能在
  高亮上用。mark 与 diff 重叠时，diff 底色 + mark 下划线共存。
- **零回归设计**：`renderMarks` 被测试钉住的块内实现**一字不动**（测试抽取
  `// ── 噪点批注` … `// 选中 / 点删的委托` 之间跑 node）。块外包一层：
  ```js
  const renderMarksPlain = renderMarks;
  renderMarks = function(){
    renderMarksPlain();                 // 列表 / hint / 无 diff 时的正文都走老路径
    if(!diffOn || typeof DiffLite === 'undefined') return;   // diff.js 没加载也不崩
    if(diffStale){ diffSpans = DiffLite.highlightSpans(curRaw.A, curRaw.B); diffStale = false; }
    $('#rv-a').innerHTML = DiffLite.composeHtml(curRaw.A, marks.A, diffSpans.A, MARK_KINDS);
    $('#rv-b').innerHTML = DiffLite.composeHtml(curRaw.B, marks.B, diffSpans.B, MARK_KINDS);
  };
  ```
- 持久化 `rv_diff`；开关旁明示偏倚提示，开启时正文上方显示图例
  （A 栏=被改掉的 / B 栏=新写的 / 改动少的一侧可能显得更稳）。

### D 验证
- `tests/test_diff_js.py`（10 条，node 跑真实 diff.js，部分用例**与批注块同进程跑**）：

  **composer 剥标签后与原文逐字相等（含 mark 与高亮重叠）**、
  **无高亮时 composeHtml 与 buildMarkedHtml 逐字相等**、mark 覆盖范围在有高亮时不变。

- 服务重启 + 浏览器冒烟（程序化断言，非截图——本会话模型不接收图片输入）：

## 自审查发现（Findings）

| # | 严重度 | 发现 | 处理 |
|---|---|---|---|
| 1 | P2 | composer 把一条与 diff 高亮重叠的 mark 渲染成**多个 mark 片段**（同 `data-mid`）。点删任一片段删除整条（委托按 id 过滤），但视觉上一条批注会被 diff 底色切成几段 | 已确认行为正确（底色+边框共存是设计意图），hint 计数按 marks 数组计不受影响。不做特殊处理 |
| 2 | P3 | diff.js 加载失败时降级为无高亮渲染（`typeof DiffLite === 'undefined'` 守卫），但用户不会收到提示 | 可接受：功能静默降级，批注流完全不受影响 |
| 3 | P3 | 深色下 toast 是浅底深字（反相设计），与浅色模式相反 | 刻意为之（深色下浅色 toast 对比度更高） |
| 4 | P2 | **骨架屏本地几乎看不见**：本地 fetch 太快（<120ms），shimmer 一闪而过。公网隧道下才有感知 | 属预期：它只在慢网络下起作用，不是每次都该看见 |
| 5 | P3 | `text-wrap: pretty` 在旧浏览器不生效（无前缀 fallback） | 渐进增强，不影响功能 |
| 6 | P3 | diff 默认关，但**一旦开启会持久化**，下次进来仍是开 | 符合"设置持久化"整体设计；且开关在工具栏一眼可见 |

## 残留风险
1. **diff 偏倚**（已知，已明示）：改动少的一侧显得更稳。开关默认关 + 图例提示兜底，
   但**不能**排除集霸开着它判了一批后数据被系统性影响。若要更稳，可考虑只在复盘页开、
   判定时禁用——本次未做（集霸明确要的是开关）。
2. **k0–k6 深色版是目调的**，未做 WCAG 对比度量化。深色下 diff 底色（红/绿）与批注 7 色
   的可区分性靠令牌分层，但没用对比度工具量过。
3. **视觉质感未经肉眼复核**：本会话模型不接收图片输入，所有视觉验证是程序化的
   （计算样式/令牌值/行为断言）。已把复核页 handoff 给集霸，结论以他看到的为准。
4. 2026-09-17 的 CTX_SCOPE / batchMulti / context_full 逻辑**逐字保留**
   （含两处⚠警告注释），未触碰；`api.py` 一个端点都没改。

## 不做的事（边界记录）
- 后端端点零改动；`MARK_KINDS` 只读不改（历史数据依赖字符串）。
- 批注块逐字不动（测试钉住的契约）；所有 DOM id 保留。
- 无客户端预取队列、无顺序揭示、无 swipe 手势（用户未选）。

# 第三轮（2026-09-18 · 紧急修复）：入场动画把 A/B 卡整卡弄隐形了

## 事故还原（这是「还是不行」的真正来源，不是"设计还不够好"）
Round 2 我加了一条 `#rv-ab.fresh .ab-card{animation:cardIn .34s ... both}`，
关键帧 `from{opacity:0}`。当日贴的验收截图全都正常，但那是"动画已播完"的情况。
真实触发态：标签页切后台/绘制节流/刚刷新后的某些时序下，Web Animation 会停在
pre-start 窗口里，fill:both 会把 `from{opacity:0}` 定格——**两张正文卡整体透明，
下方只剩 dock 的"黑洞"状态**。集霸打开页面看到的就是这个（上轮"效果不佳"之后
我自己截图也抓到了同款空洞，当时把它当作'内容未加载'误判）。

**修法是删能力不是调概率**：关键帧只保留 `transform:translateY(8px)`，**永不碰 opacity**。
最坏情况是卡在偏 8px，而绝不可能是"看不见"。

教训（写进记忆）：**页面入场动画若涉及"从 0 淡出"，就只配在"坏掉也只是不播"的方向上做**——
动画的设计目标是"加了更好看"，不是"必需才能显示内容"。

## 顺手做的景深修正
- rv-top / ctx 卡片降回平面（取消 box-shadow），只有 A/B 卡与 dock 保持浮起；
  一张页脸上"每张卡都浮一点"反而比一张卡都不浮更廉价。
- 浅色底 `#f6f5f2 → #f3f1ec`，卡片浮起对比更清楚。

## 验证
- 三套前端契约 23 绿；全量 251 全绿（EXIT=0）。
- 浏览器双主题实截图：浅色（A/B 卡可见、景深分层对、纸底与卡分得出）、深色
  （重启刷新后两轮截图，卡片 opacity=1）。
- 无新增 JS 接口、无 DOM id 变更、钉住的批注块逐字未动。

## 上一轮遗留备注修正
Round 2 里"卡片已播完了所以看不见"算是我把故障当成了正常样本——这次截屏复现的
两次记录（一次看不到、一次看得到，同 URL 同数据）钉死了根因。以后判定视觉问题
**先验证"看得到基本块"，再谈美学**——这个教训也写进记忆。

# 第四轮（2026-09-18 · Round 4）："没啥变化"追因 + 高级感升舱

## 追因"没啥变化"
三件事叠加：① 他大概率没刷新或命中了启发式缓存（`/` 早已 no-store，但弹窗内的

  （color-mix 85% + backdrop blur），A/B 徽标加大到 24px 并带"候选稿"副标。
- **dock 用具化**：圆角 14、强键 padding 11×24 字 14.5、键帽 kbd 更实。
- **队列卡降级为 chrome**：`#tab-review > .card` 去边去影，压成一行文字级 tab。
- 深色 --paper-bg 调到 #262220（卡片与底分离开）；"高级感"在暗色下主要来源是这张卡的温深比。

## 验证

- 浏览器实截：浅色（18.5px、全默认态）+ 深色（全默认态）两张都在验收时抓到了队头题、
  层级、按键层级全部按预期；测试期 localStorage 全清。
- 钉ification 契约未动：批注块/lib 块逐字、DOM id、MARK_KINDS、batchMulti/CTX_SCOPE 全部保留。

# 第五轮（2026-09-18 · Round 5）：去 GitHub 借脸——冷纸/石墨双调 + 印刷对齐

## 参考来源
- **Vercel Geist**：中性色去彩化、严密 10 级灰阶、克制使用强调色。核心启发——
  "彩色少才显得贵"，金色只做强调而不是底色。
- **Linear**：近黑底 + 纯灰结构线 + 单一饱和主色的量感比例；浮层靠模糊背景。
- **微信读书/Apple 排版惯例**：中文印刷用两端对齐（justify + inter-ideograph）。
