# 策略统计证据分档（lg-stats-evidence-class2，2026-09-26/27）

## 0. 背景与问题

`strategy_stats` 投影按**观察证据**口径报数（verified 实例计数），历史上不
区分「观察证据」与「K3 可用证据」。审计非阻断项：统计 82 条 benchmark 实
例时没做该区分——K3 查询只接 `verified` 且**排除 benchmark 基准段**（准入
判据在 `app/knowledge_query.py`，本文 §3 逐字引用）。于是「82 条实例有证
据」与「K3 真能用的证据」是两个数；2026-09-26 简报把前者当后者读
（「reviewer_version 83/83」实为 20/63 空）正是该误读形态的实例。

本轮交付：①只读盘查（§1 字段口径逐条表）；②分档新增投影字段
`extras.k3_eligible_instances` / `extras.k3_eligible_root_works`（§2），
口径与 `knowledge_query` 准入判据**同判据派生、不另写一套**（§3）；
③回归测试 `tests/test_strategy_stats_evidence_class.py` 钉住
「benchmark 有证据 / 非 benchmark 有证据」两组样本只有后者进
`k3_eligible_*`，且既有字段值逐条不变（§5）。

## 1. 只读盘查：当前投影每个字段的口径

写入方唯一：`scripts/strategy_stats_rebuild.py::compute()/run()`；
表定义 `app/models.py::StrategyStats`。口径三分类标注：
**观察证据口径** / **K3 可用口径** / **桥接（两口径对照）或非证据字段**。

| 字段 | 计算式（现状） | 口径标注 |
|---|---|---|
| `id` `strategy_id` `strategy_version` `snapshot_at` | 行标识/快照时刻 | 非证据语义 |
| `data_fingerprint` | sha256(全部实例行 `id:status:span:evidence_sha256`) | 非证据语义（覆盖任何 status，两种口径都无关） |
| `attempts` | 该策略实例行总数（任何 status） | **观察证据口径** |
| `valid` | `status == "verified"` 行数——**含** benchmark 基准段、无登记、fixture 来源、契约外文本版本的实例 | **观察证据口径**（既有语义，本轮逐字不动） |
| `rejected` | `status ∈ {rejected, rejected_evidence}` | 观察证据口径 |
| `missing` | `attempts − valid − rejected`（proposed 等） | 观察证据口径 |
| `unique_source_intervals` | verified 实例去重 `(根作品, evidence_sha256)` 数——**含基准段实例** | 观察证据口径 |
| `root_works` | verified 实例经 `work_sources.canonical_work_id` 回连的 distinct 根作品数——**含基准段所在根** | 观察证据口径 |
| `known_authors` / `genres` | 上述根作品的登记 `author_id` 非空数 / `genre_ids` 并集 | 观察证据口径（跟随 `root_works`） |
| `counter_examples` | contradicts 知识边数（knowledge_links 无写入流，恒 0 起步） | 非证据实例口径（独立线） |
| `extras.by_root_work` | 每根作品 verified 数 | 观察证据口径 |
| `extras.usable_evidence` | `kq._evidence_for(s, id, {})[1]`＝K3 保留的唯一 `(根作品, span)` 区间数 | **K3 可用口径**（区间级；服务端封底 policy、调用方收窄不含） |
| `extras.benchmark_stripped` | `kq._evidence_for(...)[2]` 中 `:benchmark_source` 后缀条目数 | **旁证**（会审 2026-09-27 修正：原文「差距的构成项」不成立）：本字段是**实例级**，`usable_evidence` 是**唯一区间级**——非 benchmark 实例落 `mirror_dedup` 时 `valid − usable_evidence` 有本字段解释不了的部分，**不构成恒等式** |
| `extras.k3_eligible_instances` **（本轮新增）** | 同一次 `_evidence_for` 调用第 1 返回值 `len(refs)` | **K3 可用口径**（实例级） |
| `extras.k3_eligible_root_works` **（本轮新增）** | 同一次调用 `refs` 中 distinct `canonical_work` 数 | **K3 可用口径**（根作品级） |

既有字段（含列字段与 extras 既有键）的计算式与语义**逐字未动**；分档字段
只旁路追加进 `extras`，读表方无静默语义漂移。

注记（如实声明）：当前实现里 `k3_eligible_instances` 与
`usable_evidence` 数值恒等——refs 与 intervals 在 `_evidence_for` 内一一
对应产生（每个被接纳实例引入一个唯一 `(根,span)` 区间，镜像重复落
`mirror_dedup` 剔除）。保留两字段是因为计数**单位**不同（实例 vs 唯一区
间），日后判据链任何一侧变化（如接纳重复区间）时两档独立可见，不必再猜。

## 2. 分档字段定义

- `extras.k3_eligible_instances` = 该策略经 K3 准入判据链实际保留并出具
  引用（refs 条目，含 `instance_id`）的证据实例数——基准段 / 无登记 /
  禁用来源类型 / 禁用用途 / 不合格文本版本 / 镜像重复全部已剔除；
- `extras.k3_eligible_root_works` = 上述 refs 覆盖的 distinct canonical
  根作品数——即「K3 视角的独立复现根数」，与观察口径 `root_works`
  （含基准段根）显式分离。

与 `usable_evidence` 同限制：按**服务端封底 policy**（空 policy）计，
调用方按请求收窄不含。82 条 benchmark 实例的形态（全部来自 4 本
benchmark 源书的基准段，见 `docs/策略卡合并方案_20260923.md`）在分档下
直接可见：`valid` 照旧、`k3_eligible_*` 归零。

判据来源 `app/knowledge_query.py`（引用行号为该文件现状行号）：

ELIGIBLE_INSTANCE_STATUS = frozenset({"verified"})

`_evidence_for` 的实例查询与剔除链（251–254、255–258、281–296 行节选，
benchmark 剔除即本分档的核心差异点）：

```python
    instances = (s.query(StrategyInstance)
                 .filter(StrategyInstance.strategy_id == strategy_id,
                         StrategyInstance.status.in_(
                             ELIGIBLE_INSTANCE_STATUS)).all())
```

```python
    seg_role = {sid: role for sid, role in s.query(Segment.id, Segment.role)
                .filter(Segment.id.in_(seg_ids)).all()} if seg_ids else {}
```

```python
    for ins in instances:
        r = reg.get(ins.work_id)
        if r is None:
            stripped.append(f"{ins.id}:no_registry"); continue
        if seg_role.get(ins.segment_id) == "benchmark":
            stripped.append(f"{ins.id}:benchmark_source"); continue
        if r.source_type in excluded_types:
            stripped.append(f"{ins.id}:excluded_source_type:{r.source_type}"); continue
        if set(r.license_purposes or []) & excluded_uses:
            stripped.append(f"{ins.id}:excluded_use"); continue
        if ins.text_version not in allowed_tv:
            stripped.append(f"{ins.id}:text_version:{ins.text_version}"); continue
        key = (r.canonical_work_id, ins.span_start, ins.span_end)
        if key in seen_intervals:
            stripped.append(f"{ins.id}:mirror_dedup"); continue   # 镜像重复不计
        seen_intervals.add(key)
```

对齐方式（**同一判据链，不另写一套**——本项目反复出现的缺陷形态是本地
复刻剔除链导致虚高，复审实跑「SSR usable 6 vs K3 真实 ev_count 2」）：
`strategy_stats_rebuild.compute()` 每策略只调用**一次**
`kq._evidence_for(s, st.id, {})`，三个新档位全部取自该次返回值：

```python
        refs, ev_count, stripped = kq._evidence_for(s, st.id, {})
        ...
            "usable_evidence": ev_count,
            "benchmark_stripped": sum(
                1 for t in stripped if t.endswith(":benchmark_source")),
            "k3_eligible_instances": len(refs),
            "k3_eligible_root_works": len(
                {ref["canonical_work"] for ref in refs}),
```

投影侧不存在任何独立实现的准入判据；`ELIGIBLE_INSTANCE_STATUS` 放宽、
benchmark 剔除调整或排除集变化时，分档字段自动跟随，无第二处需要同步。
