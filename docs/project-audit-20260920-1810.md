## P1：优先修复

### A01 盲评页面重新出题，会覆盖旧页面的 A/B 含义

位置：[api.py:421](F:/agi/language-genome/app/api.py:421)、[api.py:288](F:/agi/language-genome/app/api.py:288)、[api.py:566](F:/agi/language-genome/app/api.py:566)。

每次出题重新随机排列，却只按 `review_id` 存一份全局映射；提交只有 `winner=A/B`，没有本次出题的标识。两个页面打开同一题，或旧页面仍在时重新出题，会让旧页面的选择按新映射解释。

已用实际 API 和临时数据库复现：第一页 A=原文，第二页 A=候选；第一页提交 A，服务返回 200 并记成 `candidate`。这会污染最昂贵的用户偏好标签，批注归属也受影响。

修复：每次出题创建不可变的 `presentation_id`，持久化排列、文本哈希和上下文版本；提交必须绑定该标识。验收须覆盖双页、同题重出、重启、多 worker 和过期呈现。

### A02 片段模型的分组标签与样本顺序错位

位置：[flavor_span.py:81](F:/agi/language-genome/scripts/flavor_span.py:81)、[flavor_span.py:95](F:/agi/language-genome/scripts/flavor_span.py:95)。

`groups` 按“每题正例、负例”交错追加，最后 `texts` 却按 `pos + neg` 排列，标签没有同步重排。`group_folds` 因而不能保证同题整体进入同一折。

3 题、9 个样本的隔离复现中，5 个样本组别错误，3 个真实来源都跨了验证折。这会使“按题交叉验证”的泛化证据失效；通过该路径得到的历史 AUC 需要对照版本重算，不能继续直接用作效果门。

修复：一次构造 `(text, y, source_group)` 记录，再统一拆列；验证每个原始题目在一轮划分中只出现在一侧。重新生成数据、模型和指标，不只修改注释。

现场文件已有 `c41`、`rj1`、`rj2` 等测试批次键，说明隔离问题已经影响实际文件；仅据当前内容不能确定是哪一次历史测试造成。本次审查先重定向测试游标，确认测试前后真实文件哈希一致，未重复污染。见 [已有测试痕迹](../../outputs/project-audit-20260920-181014/cursor-existing-test-keys.json)及[本次隔离证明](../../outputs/project-audit-20260920-181014/lg-suite-isolation.json)。

### A05 实验网关隐藏重试，调用次数、token 和失败率少记

位置：[gateway.py:321](F:/agi/language-genome/app/gateway.py:321)、[gateway.py:337](F:/agi/language-genome/app/gateway.py:337)。

空正文、可重试 HTTP 状态和传输异常在循环内继续派发，通常只记录最后一次结果。实验引擎又把 `llm_calls` 作为唯一费用/失败账本，因此报表不能反映真实请求尝试。

MockTransport 复现：两次上游请求报告合计 45 token，账本只有一条成功记录、15 token，第一次失败消失。这是计量逻辑复现，不是对真实金额的估算。

修复：每次派发先预留、每次返回单独结算，区分逻辑调用与 HTTP 尝试；保存截断/错误请求的已有 usage，未知费用保持未知。此问题在实验用 `app/gateway.py`；新场景 Runtime 的单次派发适配器不走该重试循环。

### A06 网关将非空的截断输出当作成功

位置：[gateway.py:348](F:/agi/language-genome/app/gateway.py:348)。

代码读取 `finish_reason`，但只拒绝空正文。`finish_reason=length` 且正文非空时仍返回 `status=ok`。复现返回“尚未写完的半句”，调用状态仍为成功；自由文本候选可能因此以完整样本进入重建与后续评审。

修复：明确接受的完成原因，截断/过滤/不兼容完成方式均记录为非完整产物；保存用量后进入有上限的恢复流程。测试不能只覆盖“截断且空文本”。

### A07 同一实验并发运行会重复执行阶段

位置：[api.py:171](F:/agi/language-genome/app/api.py:171)、[engine.py:497](F:/agi/language-genome/app/engine.py:497)、[engine.py:511](F:/agi/language-genome/app/engine.py:511)。

API 的“检查 running”和后台线程中的“写 running”不在一个原子领取操作内；引擎自身也没有排他运行凭据。CLI 与 API 同时启动、双请求竞争，都可能读到阶段尚未完成。

两个线程对同一实验的同一阶段调用 `engine.run`，通过屏障控制顺序后，阶段体执行 2 次、两边都返回成功。复现只用了计数夹具，没有付费模型请求；真实阶段则可能重复生成和计费。

修复：数据库条件更新领取执行权，绑定 owner/lease，提交阶段结果时校验持有权；UI 禁用按钮或单纯读 status 不能替代领取事务。

### A08 Distiller 租约失效后仍可产生“完成”事件

位置：[ledger.py:281](F:/agi/novel-distiller/src/novel_distiller/ledger.py:281)。

`complete_task` 在事务外检查租约，事务内 UPDATE 不检查受影响行数，随后无条件写 `task.completed` 并返回 True。另一连接若在两者之间收回租约，旧 worker 的 UPDATE 实际为零行，却仍宣布完成。

两连接隔离复现：先通过租约检查，再由另一连接调用 `mark_interrupted`；旧提交返回 True，任务仍是 `interrupted_unknown`，事件序列却同时包含 unknown 和 completed。现有测试只覆盖进入方法前就已经错误的 token，没有覆盖检查后的竞争。

修复：在同一写事务中核验租约、检查条件 UPDATE 的 rowcount，再写完成/失败/outbox；同时复核 `fail_task`、`mark_needs_input` 的类似无条件事件路径及输入 stale 检查时机。

### A10 Verifier 抽取错误仍会消耗 Writer 修稿额度

位置：[pipeline.py:126](F:/agi/language-genome/app/scene_runtime/pipeline.py:126)、[pipeline.py:149](F:/agi/language-genome/app/scene_runtime/pipeline.py:149)。

当前仅把 JSON/引文等错误送回核验器；把未变化事实错误列为 change，或抽取值类型不对，会作为 `state_patch_not_authorized_by_plan` 驱动 Writer 重写。

隔离复现中，正文和计划事件不变，仅核验器多列 `lamp.lit=false` 这一未变事实，就触发 3 次 Writer、3 次 Verifier 并耗尽修稿额度。上一阶段第三场也曾因未变化的两枚钱被误列补丁而多改一次正文。

修复：区分正文事实缺陷与核验工件缺陷；已识别的抽取错误进入有上限的核验返修，不改正文、不忽略未经确认的状态变化。增加“正确正文 + 错误核验”的测试。

### A11 多段基准上下文的内容隔离存在空隙

位置：[export_training.py:107](F:/agi/language-genome/scripts/export_training.py:107)、[export_training.py:126](F:/agi/language-genome/scripts/export_training.py:126)。

当前只给整个 context 算哈希。基准 context 是“段落 A + 段落 B”时，单独把 A 作为训练目标或前文不会命中整个 context 的哈希。

构造 70 字段落 A 的隔离复现中，它完整出现在基准 context 内，训练闸门仍放行。现场 1,429 条基准中，当前没有双换行拼接的 context；因此这是已复现的扩展路径漏洞，不能拿它解释 A03 的全部现场重合。

修复：冻结上下文时同时保存源段 ID、边界和各段内容哈希；训练目标和实际输入都按段/窗口隔离，避免拼接形式变化绕过检查。
