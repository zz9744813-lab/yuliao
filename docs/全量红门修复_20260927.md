## 2. 修法，以及「为什么这不是绕过」

### 2.1 红 A：每例独占一个临时库（零共享），不再清表

`_isolated_db` 现在完全不发任何 `DELETE`：

```python
root = tmp_path_factory.mktemp("sc_streaming_db")
app_db = str((root / "app.db").resolve().as_posix())
monkeypatch.setattr(db.config, "DATABASE_URL", f"sqlite:///{app_db}")
isolated_engine = db._make_engine()          # 与生产同口径：sqlite + WAL + foreign_keys=ON
monkeypatch.setattr(db, "engine", isolated_engine)
monkeypatch.setattr(db, "SessionLocal", sessionmaker(bind=isolated_engine, ...))
db.init_db()                                 # create_all + _migrate 落在隔离引擎上
```

收尾 `finally` 里 `isolated_engine.dispose()` 后再 `shutil.rmtree`（Windows 下先断连才删得掉
`.db/-wal/-shm`）。`monkeypatch.undo()` 在 fixture yield 之后才跑，所以打桩与还原顺序安全。

**为什么选它、不选立案口径 ③（按外键拓扑序清表 + 删除期间显式关外键）**：

- 抄外键闭包：全库 22+ 张表要抄进测试，抄漏一张照样红，而且这份清单会随模型演进**静默失效**；
- 关外键：等于在本套件唯一的外键约束防线上开一个窗口；而且它仍然在**删别的文件留下的行**，
  把「本文件自扫门前雪」升级成主动制造跨文件污染；
- 零共享：新建的空库里根本没有别人的行，既不需要 DELETE，也不需要动 `PRAGMA foreign_keys`
  （保持 ON ⇒ 本文件若真造出违反外键的数据，照样红）。

**为什么不是绕过**（对照立案禁止项）：

- 没有 `-p no:randomly`、没有 `--forked`、没有 `deselect`/`-k`/`--deselect`、没有改收集顺序或
  `conftest.py`；用例名、数量、断言一个字未减（仍是那 30 个用例、同样的逐值对照断言）。
- 反而**收紧**了不变量：这些用例本来就在断言「计数恰好等于我自己铺的数据」
  （`tot/checked/ok/bad/unverified`、分页序列严格升序等）。在共享库上这个断言
  只是碰巧成立（别人没留相关行时才成立）；换独占库后它成为**结构性成立**。
- 链路自证：`_spy_pages` 读的是 `db.engine`（晚绑定，拿到隔离引擎）；
  `test_nonbench_paging_uses_session_per_batch` 打桩的是 `sc.db.session`，
  还原后 `db.session()` 仍从被打桩的 `db.SessionLocal` 造会话 ⇒ 全程落在隔离库上；
  `source_check.run()/scan()` 只经 `db.session()` 取会话，不缓存引擎。

### 2.2 红 B：期望值改为**从只读真库现算**的参考实现（oracle），不是把断言改松

新增 `_oracle_package(s, policy)`（`tests/test_brief_cost_numbers.py`）：
只 `SELECT` 原始行（`expression_strategies_v2` / `strategy_instances` / `segments` /
`work_sources` / `strategy_conditions`），自己完成 C 场景下的选包集合语义；
**一行都不调用**被测的 `KQ.query_knowledge` / `_evidence_for` / `_scope_matches`
（不是拿被测代码算期望再拿被测代码算实际来自证）。

镜像步骤与被测管线的对应关系（逐步可查）：

| 参考实现里的一步 | 对应 `app/knowledge_query.py` |
|---|---|
| `st.status not in KQ.eligible_statuses(st.version)` 跳过 | 层1a status 资格集 |
| `st.observation_status not in KQ.ELIGIBLE_OBSERVATION` 跳过 | 层1b 观察资格 |
| `_c_eligible_intervals()`：有登记行 / `role != "benchmark"` / `source_type` 不在 `KQ.DEFAULT_EXCLUDED_SOURCE_TYPES` / `license_purposes ∩ KQ.DEFAULT_EXCLUDED_USES == ∅` / `text_version ∈ KQ.DEFAULT_ALLOWED_TEXT_VERSIONS`，实例 status ∈ `KQ.ELIGIBLE_INSTANCE_STATUS`，按 (根作品, span) 聚合 | 层2 `_evidence_for` 六道硬拦 |
| `_c_condition_gate_ok()`：C 场景 `semantic_requirements={}` ⇒ 只有「非 bad_when 且非 required 的 good_when」能过 | `evaluate_predicate` + `_condition_pipeline` |
| `_oracle_scope_ok()`：取**策略行内存里的当前值** `st.scope`/`st.scope_ids`（`apply_scenario` 已把 `<BOOK>` 代入）；WORK→book 命中 scope_ids，AUTHOR/GENRE 经登记行反查，GLOBAL/UNCERTAIN 一律拒 | 层3 `_scope_matches` |
| 同 `strategy_key` 取最高 `version` | 同 key 版本去重 |
| `sorted(..., key=(0, 0, -len(intervals), -KQ.SCOPE_SPECIFICITY[scope], strategy_key))[:cap]`（前两个 0 = `{}` 需求下 required/good_when 分量恒 0） | 分量排序 + `candidate_cap`（`cap` 取自 policy，默认 `KQ.CANDIDATE_CAP_MAX`） |

门禁取值全部**引用 `app.knowledge_query` 的常量**而非抄字面量：口径搬家时参考实现跟着搬，
搬完两边不等就会红 —— 这正是「独立对照」想要的信号。

断言的变化（`selected_ids` 是关键字段）：

```python
# 旧（快照）
assert observed["selected_ids"] == (STRATEGY_ID,)
assert observed["evidence_root_works"] == ((QIONGMING,),)
# 新（推导 + 逐值含顺序对照）
assert observed["selected_ids"] == observed["oracle_selected_ids"]            # ← 等式强度不降
assert observed["evidence_root_works"] == observed["oracle_evidence_root_works"]
assert STRATEGY_ID in observed["selected_ids"]    # 叙述前提的显式钉子（带人工复核文案）
```

**为什么这不是「放宽断言买绿」**（立案明确禁止只改成 `assert STRATEGY_ID in ...`）：

- 期望值仍是**逐值、含顺序的等式**，覆盖整包内容（不止那一条策略），并且额外钉了每条
  包项的证据根作品集合 —— 比原来「只认一条 id」的覆盖面**更大**，不是更小；
- 单独把断言松成 `in` 是被禁止的，所以它只作为**附带**的叙述钉子保留，且失败信息写成
  「ESV2-0450910b989f 不再出现在琼明 C 包里 —— 反事实代价算术的叙述前提已变，
  须复核后更新本钉子」：这条红**要求人来改叙述**，不接受静默换血；
- 推导依据写进了用例文件 docstring（§「本包选中的到底是哪几条策略」= 推导，不是抄答案）
  与本节：**判据 = K3 在 C 场景下的选包语义**，参考实现是它的独立复写；
- 「数据再变会怎样」：夜间写入继续进来（新策略/新实例/新证据）⇒ 期望值与被测值
  **一起**变，门不颤；只有「K3 选包逻辑与参考实现不再同义」（改了管线没同步这里，
  或反过来）才转红 —— 那是一次真事件，不该被噪声掩盖。

**新增的前置 skip（不是买绿）**：`c_cost_observation` 里加了「真库没有 `ESV2-0450910b989f`」
「缺 FUHAN/QIONGMING 来源登记行」两条 skip。它们保护的是**本叙述的成立前提**（这条策略
与这两个作品是简报点名的对象）：前提被删（作品/登记被删）时，用例不该把「语料被删了」
误报成「选包口径漂移」，也不该在缺前提时仍硬跑等式。这与本文件既有写法一致
（真库缺失/不可读已经是 skip 口径），并且**不影响红 B 本身**：红 B 发生时库和前提都在。
