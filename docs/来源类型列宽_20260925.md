# work_sources.source_type 列宽与合法取值不一致（审计口径收口，2026-09-25）

## 结论一句话

`source_type` 列宽从 `String(20)` 放宽为 `String(64)`，并在登记写入口
（`scripts/register_work_sources.py`）加上超宽硬校验。口径风险是「换库
即炸」的审计隐患：SQLite 不校验 `String` 长度所以现状能跑；同一套代码
换 Postgres/MySQL 时，被设计为合法取值的 28 字符值会立刻 `value too
long`。

### 1.4 真库现状（只读，未做任何写入）

对 `data/language_genome.db`（只读 URI `mode=ro`）执行：

### 1.5 结论

SQLite **不校验** `String(20)`，所以现在「能跑」；换 Postgres/MySQL
立即报 `value too long for type character varying(20)`。属**审计口径
风险**，不是当前数据已被污染。

## 2. 改动前后

### 2.1 `app/models.py`（只改列宽与其紧邻注释）

改动前：

```python
    # 来源类型：fixture / synthetic / commentary / human_fiction
    source_type: Mapped[str] = mapped_column(String(20), index=True)
```

改动后：

```python
    # 来源类型：fixture / synthetic / commentary / human_fiction / 含
    # production_nonbenchmark_ 前缀族（如 production_nonbenchmark_k2v2，长 28）；
    # 列宽 64 留余量——SQLite 不校验长度，换 Postgres/MySQL 必须能装下。
    source_type: Mapped[str] = mapped_column(String(64), index=True)
```

只改宽度：类型仍是 `String`、未加任何约束（Check/Enum 一律不加）、
索引/唯一性不变。选 **`String(64)`**：以 28 为硬下界，留约 2.3 倍余量，
足以容纳 `production_nonbenchmark_`（24）前缀族带更长版本尾号的值，也
不会大到冲击索引（VARCHAR(64) 走标准 B-tree，无前缀索引问题）。

### 2.2 `scripts/register_work_sources.py`（登记写入口硬校验）

新增 `_check_source_type_width(source_type)`：

- 读取模型声明的列宽（`WorkSource.__table__.c.source_type.type.length`）
  作为**唯一事实源**——改列宽自动跟随，不另设一份常量防漂移；
- 超宽**直接 `SystemExit` 报错退出并说明**（把长度与列宽都打印出来），
  **不静默截断、不 clamp**；
- 在 `register()` 每行 `row` 构建完成后、`rows.append` 之前调用——
  覆盖 fixture / 镜像 / 根作品三条登记分支，**dry-run 同样校验**
  （预演也要如实报出超宽，不许预演放行、真跑才炸）。

校验语义边界的取舍：只断**长度**；取值集合是否枚举化**不在本任务范围**
（见 §5 未做项）。

### 2.3 新增 `tests/test_source_type_width.py`（6 条，全绿）

1. `test_source_type_column_fits_longest_designed_value` —— 列宽 ≥ 28
   且 ≥ 全仓最长设计取值；`production_nonbenchmark_k2v2` 长度锚定 28；
2. `test_28_char_value_is_the_longest_currently_designed` —— 28 是
   当下设计取值上界，新类型超过它必须回来改列宽；
3. `test_28_char_designed_value_inserts_and_commits` —— 28 字符值经
   模型层**真插一行 + commit** 成功并原样读回（证明夹具值在模型层合法，
   换库不炸）；
4. `test_write_entry_accepts_28_char_designed_value` —— 28 字符值能过
   写入口校验（放宽后不误伤试点源）；
5. `test_validator_rejects_overwide_string` —— 超过列宽的值
   `SystemExit` 且**退出码非 0**（只断言异常、不许只断言字符串）；
6. `test_register_rejects_overwide_source_type` —— **整链路回归**：

## 3. 换库影响

| 项 | SQLite（现状） | Postgres / MySQL（换库） |
|---|---|---|
| `String(20)`（改动前） | 不校验，28 字符照样落库 | `value too long for type character varying(20)`——托管 K2 试点源即炸 |
| `String(64)`（改动后） | 行为不变 | 28 字符（及其前缀族加长版号）可正常落库 |
| 登记写入口 | 无感（现有值全 ≤ 13 < 64） | 超宽值在写入口被当场 `SystemExit`，**不会**轮到后端报错 |

换库时无需迁移存量数据（现库最长 `human_fiction` = 13，远低于新旧两档
宽度）；只需用新模型建表/对齐 DDL 后即可承接 28 字符试点源。

**明确未动**：`app/knowledge_query.py`、`app/api.py` 的排除集语义
（`DEFAULT_EXCLUDED_SOURCE_TYPES` / `excluded_source_types` 等一字未动）；
`data/language_genome.db` 真库；原始语料。

   不做任何写库动作。
