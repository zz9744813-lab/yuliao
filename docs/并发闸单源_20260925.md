`_pool_workers` / `_check_conc` 这对并发闸 helper 从 6 个旁路脚本里的 **6 份逐字复制**

### 改后（本轮）

- **单一实现**：`scripts/_conc_guard.py`（主控预置草稿 + 本轮补充 `serial_check`
  注入参数，见 §3.3）提供：
  - `check_conc(parser, value, flag="--conc")`——CLI 上/下界闸，越界 `parser.error`
    → **exit 2**；
  - `pool_workers(conc, models=(), tag="conc", serial_check=is_serial_model)`——运行时
    兜底夹到 `[1, limits.MAX_CONCURRENCY]`，命中 `app.gateway.is_serial_model` →
    workers 恒 1 并打印「串行强制」；越界/非正值/非法值打印后取边界值（不再静默）。
  - 上限真源**仍只有** `app/limits.py::MAX_CONCURRENCY` 一处，`_conc_guard.py` 只读不另立常量。
- **6 脚本只留引用**：各自删掉 `def _pool_workers` / `def _check_conc`，改为
  `from _conc_guard import check_conc as _check_conc, pool_workers as _pool_workers`，
  调用点形状、全局名、默认值（8/6/3/4/8/4）全部与改前一致。
- **默认路径零回归**：默认 conc 全部 ≤16（界内），`parse_args` 不报错，`pool_workers`
  零额外输出——与改前逐字一致。
- 6 处的 `serial_check=is_serial_model` 传的是脚本模块层持有的同一绑定
  （仍 `from app.gateway import is_serial_model`），因此既有「替换复用函数→判定跟着变」
  注入夹具不失效；**判定实现仍只存在于 `app.gateway.is_serial_model`**。

### 2. 下界闸的口径变化与理由

| 维度 | 改前 | 改后 |
|---|---|---|
| `--conc 0` / `--conc -1`（CLI） | 被 argparse 放行 | **exit 2 响亮报错**（`parser.error`），
  文案明说「低于下界 1…拒绝静默归一（下界也是闸）」 |
| 运行时 `pool_workers(0)` / 负数 | `max(1, …)` **静默**取 1，无任何打印 | 打印「越界截断」后取下界 1 |
| 运行时 `pool_workers("abc")`（非法值） | `int("abc")` 直接抛 `ValueError` | 打印「非法 conc=… → workers=1」后取 1 |
| 界内默认值（≤16） | 零输出 | 零输出（不变） |

**理由**（沿用「拒绝静默 clamp」的自述口径，两席一致点名）：命令行数值是操作者亲手声明的
意图；下界越界若静默 1，操作者会以为自己开了 0 并发（跑不动/没开）或负数被掐没，却拿到的
是「悄悄跑 1 并发」——对费用/限速护栏而言不见得比上界越界安全。同时把 `MAX_CONCURRENCY`
定在 16 的语义是护栏而非吞吐调优，下界取 1 是「至少 1 个 worker」的物理下限，越线一律不算
合法意图。运行时路径（绕过 argparse 直调函数）同样从「静默归一」改为「打印后取边界值」，
两处口径互相咬合。

### 3. `_conc_guard.py` 相对主控预置草稿的改动

1. `pool_workers` 增加 **`serial_check=is_serial_model`** 可选参数（默认即网关真身，不改默认
   语义）：脚本侧传自己模块层持有的 `is_serial_model` 绑定，保证「替换复用的判定函数 →
   脚本 worker 决策跟着变」的既有测试钉子（`test_serial_injection_flips_worker_decision`、
   `test_serial_check_reuses_gateway`）不失效。判定实现仍只 `app.gateway` 一处。
2. 模块 docstring 补充 `serial_check` 说明。其余语义按草稿原样交付，**未削弱**：
   越界 exit 2、非正值/非法值打印、串行强制打印、界内零输出。
3. 迭代过程中发现并遵守的既有测试约束（**未改任何既有测试**）：
   - `test_serial_check_reuses_gateway`：脚本必须仍暴露 `mod.is_serial_model is
     gateway.is_serial_model` → 脚本保留 `from app.gateway import is_serial_model`；
   - `test_every_executor_site_uses_pool_workers`：源码 `workers = _pool_workers(` 名字钉子
     → 脚本用 `as _pool_workers` 别名引用，局部名不变；
   - `test_no_second_literal_cap`：源码需含 `limits.MAX_CONCURRENCY` → 脚本保留
     `from app import ..., limits` 与工具提示里的 `{limits.MAX_CONCURRENCY}` 引用。
