## 4. 泄漏分析（临时世界目录）

改动前逐路径核查（`main()`，`tmp=mkdtemp` 于 line 433）：

| 路径 | 改动前行为 | 判定 |
|---|---|---|
| 离线正常/失败/异常 | finally `not a.live → rmtree` | 不泄漏（保持） |
| live 正常收口（含 failures 非零退出） | 目录留库——tokens 对账（收据之和 vs calls 表之和）要读 `arm*/k4.sqlite`，**有意保留**，收据现已记址 | 非泄漏（证据） |
| **live 异常/中断**（mkdtemp 后、收据打印前抛异常：会话/分析/打印/落盘炸，或 R6 之外的注入故障） | finally 仍走 `if not a.live` 的 else——**什么都不做**：目录留在系统临时区，且没有任何收据引用它（产物 JSON 从未产出）→ **真泄漏**：不可定位、无人清理、逐次真跑累积 | 泄漏路径（本次收口） |

保守清理口径（line 477–483）：

- 仅当 `live 且 receipted=False`（收据从未对外可见）触发；
- 只删 `tmp` ——本次 `tempfile.mkdtemp`（O_EXCL 原子、名字随机唯一）自建的
  目录，**函数作用域内不可能指向他处**；`ignore_errors=True` 与离线分支同口径；
- 绝不按名字前缀扫系统临时目录、绝不做「批量清理」——防误删他人/历史留库；
- 事实留痕：stderr 打印含 `worlds_dir_cleaned=true`（此时收据不存在，
  stderr 是唯一落点；正常收口路径该事实记在收据 `worlds_dir_cleaned=False`）。
