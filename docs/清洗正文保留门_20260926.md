## ② 清洗正文保留门的语义（已实现）

入口：`preserve_gate_write(seg, new_value, *, overwrite, via)`——`polish` 与
`run_llm` 两条会**覆写非空正文**的写路径落 `text_clean` 的唯一入口。四态：

1. 旧值为空（None/空白）→ `'write'`：正常首写，门完全不介入、不留痕
   （**不改正常路径**——「不许把正常路径也拦死」）。
2. 旧值非空、新值去空白后与旧值相同 → `'identical'`：幂等跳过，不算事件。
3. 旧值非空、未授权越门 → `'blocked'`：**默认拒写**。旧值原地保留（不静默丢旧值），
   该段记「**待人工裁决**」：`segments.integrity` JSON 增
   `text_clean_preserve_gate` 键（`status=pending_review` + via + 旧/新值 sha256 与
   长度），留痕口径借 `import_corpus_v2` 的「JSON 键留痕、不加新列」风格；
   同时落一条 `pending_review` 审计事件。`integrity` 解析不出 JSON 对象时**不重写**
   它（不猜别人的留痕），事件仍全量落审计日志。
4. 旧值非空、显式越门 → `'overwritten'`：仅当 `--overwrite-text-clean`
   （函数参数 `overwrite=True`）；写入新值，**旧值全文 + sha256** 落审计事件，
   并清除该段待裁决标记。

串接顺序：`run_llm` 内**内容质量门在前、保留门在后**——被 `guard_verdict` 拒的结果
计 `llm_rejected`，根本不进保留门（不产生覆写裁决）。
`run_rules`（`:289`）盘查确认不构成覆写，不入门、逐字维持原样（仅加注释）。
不新增任何清洗规则、不改任何清洗口径——门只决定「这次落笔写不写」。

CLI：`--overwrite-text-clean`（默认关）。统计新增 `_stat["gate_blocked"]` /
`_stat["gate_overwritten"]`，`polish` 返回 `gate_pending` / `gate_overwritten`，
`--llm` 完成行打印「覆写拒写 / 越门覆写」计数。`--polish/--llm --dry-run` 的预报
口径维持「加门前规则还会改多少段」（残留普查用），不受门影响。
