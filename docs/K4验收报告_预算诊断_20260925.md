## 2. 消费侧口径（本报告交付，`_self_consistent` 机械判据③）

对 `call_budget_exhausted` 的「诚实」判定，三级次序：

1. **硬证据优先**：`budget_diag` 存在、无 `store_unavailable` 且
   `actual_calls` 为 int ⇒ 判据为
   `budget_diag.actual_calls == budget_diag.max_calls`。
   - 相等 ⇒ 诚实（依据落「budget_diag 硬证据优先：actual_calls=N，
     max_calls=M（configured=…，failed_calls=…，repair_calls=…）」）；
   - 不等 ⇒ **defect（口径缺陷未定）**——预算未用尽却声称预算闸拒，
     diag 能推翻仅凭世界库行数得出的旧口径诚实结论。
2. **退回旧口径**：无 `budget_diag`（旧收据，即
   `out_k4_3_mc22_v2/k4_paired.json` 形态）、或
   `store_unavailable=true`、或 diag 无 `actual_calls` ⇒ 走改动前的
   世界库逐行核对（calls 行数 == `budget.max_calls` 且全
   succeeded、job 非 committed）。**不许因缺字段翻判 defect**。
   世界库 request 未记预算时生效上限回退取收据 `budget_calls`
   （旧收据两者皆无 ⇒ 口径不变）。
3. **不许静默**：`store_unavailable=true` 时依据里必须出现
   「budget_diag.store_unavailable=true ⇒ 诊断取数失败，退回旧口径
   （世界库逐行核对）」；`budget_diag` 原文（JSON）逐条落进失败行的
   basis，连 `rollback_failed` / 世界库不可读等早退分支也不吞字段。

边界钉：`budget_diag` **不替代**世界库核对——世界库整体不可读时仍判
「证据不足」，不凭 diag 单腿判诚实（沿用红线：缺证据绝不判通过）。
