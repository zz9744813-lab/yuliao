## 2. 多策略负例组设计

三套彼此可区分的抽象操作策略（脚本内常量），用于制造「串味」：

| 标识 | abstract_operation（摘要） | 用途 |
|---|---|---|
| A | 环境微变替代直接情绪描写（灯花跳一下）| 沿用文件顶部 `DEF` |
| B | 少动作直给疑问：以极简动作配合一句短问直戳，不给铺陈 | 本组**要验的目标** |
| C | 铺陈渲染：以层层环境景物叠加烘托情绪 | 与 B 在表层文本可重叠，制造串味 |

共用文本 `MULTI_TEXT`：
> 窗外的雨忽然停了。他没抬头，指节敲了敲桌沿，低声问：你打算瞒我到几时？

夹具模型（`_Capture`）回什么，模型就「说」什么——**没有任何真实 LLM 参与**，
所有 `observed_content` / `evidence_text` 由测试硬编码。我们钉的是
`extract_segment` 在**当前实现下**的归类行为，绝不修改实现去迎合期望。

### ① 正例（应 verified）
- `test_multistrategy_positive_B_verified_by_its_def`：给 B 定义，回 B 真实实例
  （span=`指节敲了敲桌沿，低声问：你打算瞒我到几时？`，逐字 + 合法 offset，
  observed_content 描述 B）→ **verified**；并断言 payload 带 B 四字段。
- `test_multistrategy_positive_C_verified_by_its_def`：给 C 定义，回 C 真实实例
  （span=`窗外的雨忽然停了。`，observed_content 描述 C）→ **verified**。
  与 ② 对照：同一段文本既有 B 可抽的短问、也有 C 可抽的景物烘托，
  分类正确与否取决于 observed_content 是否对应所给策略。

### ② 串味负例（实际行为钉死 + 期望行为 xfail）
- `test_crossflavor_currently_passes_known_gap`：给 B 定义，但 `observed_content`
  描述 C（「此处铺陈渲染到位……是 C 策略的典型体现」），span 仍逐字合法 →
  **实际行为：放行（verified）**。本例如实钉住现状，并断言 payload 带的是 B 定义、
  `observed_content` 含「铺陈渲染」——证明离线机械口径下实现**无法发现**这处串味。
- `test_crossflavor_should_be_blocked`（`@pytest.mark.xfail(strict=True)`）：
  期望行为——给 B 定义、observed_content 却描述 C → 应 `unverified`（拦下）。
  当前实现做不到，故预期失败。**`strict=True` 的用意**：一旦日后实现能拦下、
  本例变 XPASS，套件会**红**，强制我们移除该 xfail 并据实改写本交付，
  防止「悄悄修了又不说」。

### ③ 空定义 vs 有定义差异（多策略场景）
`test_empty_vs_defined_def_multi_strategy`：同一段文本 + 同一夹具回复，
1. `strategy_def=None`（旧口径）→ payload 旧形状 `{"strategy_id","text"}`、
   system 无「抽象操作」前缀；
2. `strategy_def=DEF_C` → payload 逐字带 C 的四字段
   （`abstract_operation`/`invariants`/`effect_hypothesis`/`failure_modes`）、
   system 有「抽象操作」前缀；
3. 多策略互不串：给 B 定义时 payload 是 B 四字段，不是 C 的。
   → 证明「给定义」确实改变了发往模型的输入，且多策略各自定义独立。

## 3. 逐条负例的**实际行为**

| 用例 | 构造 | 当前实现实际结果 | 是否期望 |
|---|---|---|---|
| ① B 正例 | 给 B 定义 + B 真实实例 | verified | 是 |
| ① C 正例 | 给 C 定义 + C 真实实例 | verified | 是 |
| ② 串味（实际） | 给 B 定义 + observed_content 描述 C | **verified（放行）** | 否——已知缺口 |
| ② 串味（期望） | 同上，期望拦下 | 期望 unverified，当前做不到 → `xfail` | — |
| ③ 空 vs 有定义 | None / C / B 三态对比 | payload 与 system 差异如 §2③ | 是 |

核心事实：**当前三道门（预算闸 / 完整输出门 `gate_output` / 证据门 `gate_evidence`）
只核 `text[span]==evidence` 逐字 + JSON 字段完整，从不比对 `observed_content`
与策略抽象操作的语义。** 因此「串味」（给 B 的定义、observed_content 却描述 C）
只要 span 是原文逐字子串，就照常 verified。

## 4. 已知缺口清单

1. **串味不可机械判（P1 第 3 条后半句的核心缺口）**
   - 现象：给某策略定义、模型回的实例却对应另一条策略的抽象操作，
     当前实现放行（verified）。
   - 根因：`extract_segment` 的输出门/证据门无 `observed_content`↔`abstract_operation`
     的语义对齐步骤，结构上就没有归类校验。
   - 钉死方式：`test_crossflavor_currently_passes_known_gap`（如实记录放行）
     + `test_crossflavor_should_be_blocked`（`xfail strict=True` 钉住期望）。
   - 修复路径（不在本离线骨架范围）：引入**模型判据**（二次判定 observed_content
     是否真在呈现该抽象操作）或**人工复审门**；届时须移除 xfail 并据实改写本交付。

2. **为什么不在 `app/knowledge_extract.py` 硬造机械判据**
   - 任务允许的机械规则示例（「observed_content 须逐字出现某不变量短语」）本身**不成立**：
     - 假阴性：正确分类可能用自有话术描述操作、不 echo 不变量原文 → 被误拦；
     - 假阳性：模型可照搬不变量短语却仍误归类（证据指向的是另一策略）→ 漏拦。
   - 即「逐字含不变量短语」≠「归了正确的类」，它测的是「有没有抄我们的措辞」，
     不是「有没有归对类」。任何不引入模型判断的硬门都会要么放宽正确抽取、
     要么新增假拒——与「不许悄悄放宽任何既有输出门/证据门」冲突。
   - 故依任务明示（「若做不到机械可判，不要硬造，只交测试 + 已知缺口说明
     （这也算合格交付）」），**不修改 `app/knowledge_extract.py`**，默认行为逐字不变，
     既有 5 例与 `test_knowledge_extract.py` 全绿。

## 5. 82 条存量实例为何仍无法机械判串味（如实说明）

审计口径：83 条 verified 实例里 82 条来自 benchmark 段，8 条策略实例分布严重不均
（单策略最多 45 条）。这 82 条「需复审」是**分布异常**暴露出来的，**不是**任何
机械串味检测器判出来的——因为离线骨架里根本不存在这样的检测器（见 §3/§4）。

具体为什么存量数据机械不可分：

1. **存储结构没有可用于机械判据的字段**。`strategy_instances` 表只存
   `strategy_id` / `span_start` / `span_end` / `evidence_text` / `observed_content`
   / `extractor_model` 等。是否「串味」取决于 `observed_content`+`evidence_text`
   是否真的在呈现**该** `strategy_id` 对应的 `abstract_operation`——
   这是语义判断，表里没有任何可计算的真值信号。
2. **证据门只证「存证是那个区间的原文」**（`verify_instance_span` 单一口径），
   不证「归纳成立」。schema 合格 ≠ 推断成立，语义归纳必须另审（代码注释原文）。
   所以即便 82 条 span 全部逐字合法，也丝毫不能排除它们是按表层内容而非抽象操作归的类。
3. **分布不均本身不能反推串味**。单策略 45 条，既可能是「该策略确实常见」，
   也可能是「模型把别的策略实例也塞进来了」——两者在现有数据下**不可区分**，
   因为没有逐条标注「这条实例到底对应哪个抽象操作」。要区分，只能对 82 条逐条
   用模型/人工重判 `observed_content` 是否匹配其 `strategy_id` 的 `abstract_operation`，
   这正是本组测试想要、但离线骨架暂不提供的判据。
4. **本组负例证明缺口真实存在**。② 的夹具构造（给 B、描述 C、span 合法）在现状下
   返回 verified，说明「只要 span 合法就入 verified」的链路对串味是透明的——
   82 条存量里若有同类实例，当前无人能靠机械手段捞出。

结论：82 条需复审是**真问题**，但「用机械方法把它从存量里挑出来」在当前离线骨架下
**做不到**；能做的、且本交付已做的是——把「给定义后是否仍按表层内容而非抽象操作归类」
这件事用可复现测试钉成回归，并明确标出修复须在哪一层（模型判据/人工复审）补。
