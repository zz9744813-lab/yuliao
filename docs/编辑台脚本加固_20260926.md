## 逐条对照

### 1. `enhanceNav` 硬编码 3 个 `.lg-nav-list` ⇒ TypeError 中断整页初始化

**会审原文**：`[一般] websrc/_shared/editorial.js:23-27 (enhanceNav)` 硬编码假设导航里恰好有 3 个
`.lg-nav-list`：`rail.querySelectorAll('.lg-nav-list')[i].prepend(section)`。若某页导航列表少于 3 个，
`[i]` 为 `undefined`，`.prepend` 抛 **TypeError**，且该函数在 `LG.init` 内同步执行 ⇒ 整页初始化中断
（静默白屏风险）。

**修法**（editorial.js `enhanceNav`）：

```js
var navLists = rail.querySelectorAll('.lg-nav-list');
['01 / 观察与材料', '02 / 判断与校准', '03 / 系统与交接'].forEach(function (label, i) {
  var target = navLists[i];
  if (!target) return;          // 存在性守卫：缺列表就跳过该分组，不抛 TypeError
  var section = document.createElement('div');
  section.className = 'lg-nav-section';
  section.textContent = label;
  target.prepend(section);
});
```

守卫放在三分组循环内部、后续「导航项编号 + 检索按钮」构建之前 ⇒ 跳过一个分组不会中断
`.lg-nav-item` 的编号与 `#lg-search-btn` 的构建（用例 (a) 同时钉住这两点）。

**收口判据**：`tests/test_editorial_js.py::test_enhance_nav_survives_missing_nav_lists` ——
导航只有 1 个 `.lg-nav-list` 时 `LG.init` 不抛异常、`idxs == ['01','02','03']`、
sections 只挂第 1 组、rail 与检索按钮均构建。另设对照用例
`test_enhance_nav_three_lists_regression_control`（3 个列表 ⇒ 三分组齐全），防守卫误伤正常路径。

### 2. refresh 失败分支重复堆叠「重新读取」按钮

**会审原文**：`[一般] websrc/_shared/editorial.js:150-160 (refresh 失败分支)` 每次读取失败都向
`#banner` 追加一个「重新读取」按钮，多次失败会**重复堆叠**。

**修法**（editorial.js refresh 的 catch 分支）：

```js
var banner = byId('banner');
// 去重：同一个 banner 上最多一个「重新读取」按钮，多次失败不得堆叠
if (banner && !banner.querySelector('.lg-banner-retry')) {
  var retry = document.createElement('button');
  retry.type = 'button';
  retry.className = 'lg-banner-retry';
  retry.textContent = '重新读取';
  retry.addEventListener('click', refresh);
  banner.appendChild(retry);
}
```

以 `.lg-banner-retry` 类做幂等标记：已存在则不再追加（顺带补了 `banner` 为 null 的防御）。
若后续 `LG.showBanner` 重建 banner 内容把按钮清掉，下次失败会重新补挂一个，行为仍正确。

**收口判据**：`test_retry_button_deduplicated_after_two_failures` —— 连续 2 次 `fetchModule` 失败后，
`#banner` 内文本为「重新读取」的 BUTTON 数量 **== 1**（class 计数与文本计数双口径），banner 处于 err 态。

### 3. `findIndex == -1` 静默降级成 `00`

**会审原文**：`[一般] websrc/_shared/editorial.js:135 (enhancePage)` `LG.MODULES.findIndex(...)`
找不到 slug 时返回 `-1`，kicker 渲染成 `RESEARCH ARCHIVE / 00`，属**静默降级**而非报错。

**修法与可判定行为**（editorial.js `enhancePage`）：

```js
// 目录里没有该 slug（findIndex == -1）时不渲染伪序号「00」，改用显式可见的「--」哨兵
kicker.textContent = 'RESEARCH ARCHIVE  /  ' + (index >= 0 ? two(index + 1) : '--');
```

**约定**：目录缺失该 slug 时 kicker 固定渲染 `RESEARCH ARCHIVE  /  --`（可见哨兵，不抛错、
不阻断页面其余初始化；`--` 与任何合法两位序号 `01..99` 互斥，可机器判定，也让人一眼看出
「此页不在研究目录中」）。已知 slug 的 `01/02/…` 正常渲染不受影响。

**收口判据**：`test_unknown_slug_kicker_uses_visible_sentinel_not_zero` ——
未知 slug 页面 kicker `== 'RESEARCH ARCHIVE  /  --'` 且不含 `00`；对照面 `m2` 页面 kicker
`== 'RESEARCH ARCHIVE  /  02'`。
