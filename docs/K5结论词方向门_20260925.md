# K5 结论词方向门（2026-09-25）

## 1. 这条门治什么病

第二轮独立复核（`REVIEW_audit_residuals_round2_20260925.md`，仓库外只读）判 **BLOCK**，唯一依据：
把 `docs/K5供给口径真计数_20260925.md` 的结论词 `不成立` 手工改成 `成立`，本仓现有验收门 100% 全绿
（复核席实测 7 条门变异前后全部 `True→True`）。

根因是**结构性错位**，不是正则写松：

- 全仓没有任何测试读取**已提交**的该文档；`grep` 只命中生成器自己的输出路径常量与 docstring。
- `tests/test_k5_supply_recount.py` 确实钉了方向（`A_n_ge==2 → verdict_ok is True`），
  但它断言的是**当场生成的临时 markdown**，手改文档不会让任何用例变红。
- 复跑 `scripts/k5_supply_recount.py`（默认模式）会**覆写**该文档把手改冲掉，验收仍 `exit 0`
  ——「自愈式无红」。

## 2. 门怎么做（零依赖、零真库、纯文本）

`tests/test_k5_doc_conclusion_direction.py` 读文档自身，不读库、不调模型：

1. 严格锚定 **§2.1（口径 A）** 小节（`### 2.1` 起、到下一个 `###` 止），只解析该节逐作品表
   （`| WK-xxxx | 书名 | 876 |`）。
2. 按生成器同一谓词复算：`n_ge = #{作品 : 段数 >= 10_000}`，达标条件 `n_ge >= 2`；
   应有结论词 = `成立`（达标）/ `不成立`（未达标）。
3. 核心判据：文档结论词集合必须**包含复算所得的那一个**。
4. 防自相矛盾：文档不得同时出现 `不成立` 与独立的 `成立`。
5. 反向自检用例：在**内存里**把 `不成立` 翻成 `成立`（不落盘、不改仓库文件），
   断言核心判据在变异文本上转红——这是门「有方向」的机械证明。

## 3. 两个已实测的陷阱（改动本门前先读）

- **四张表混解析 ⇒ 门反向失效。** 文档有 §2.1/2.2/2.3/2.4 四张表，口径 B/C 最大单作品
  154,674 / 154,809 段、`≥10,000` 段的作品有 6~7 个。若一起解析，复算结论恰好是「成立」，
  门会钉住**错误**的方向。本门另用一条断言（§2.1 内不得出现 `≥10,000` 段的行）钉住解析范围。
- **子串陷阱。** `不成立` 含子串 `成立`：必须先 `replace("不成立", "")` 再判 `成立`，
  否则「只查肯定词」会让正反两个方向都判绿（上一轮报告 §4.2 点名的那个方向性陷阱的镜像）。
- 文档不在树内时**直接断言失败**，不用 `skip`——缺文档不得静默放行。
