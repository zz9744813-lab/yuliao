### 1.3 改前判定链读出的三件事

1. **行为上已是最严的一档**：第 161–162 行「出现任一代理头 ⇒ 不按本机放行」，所以

### 2.1 路由标签化（把 bool 判定升成具名四态）

新增纯函数 `classify(host, has_proxy_headers)` 与 `access_route(request)`，返回值域：

| peer | 代理头 | 标签 | 是否需令牌 |
|---|---|---|---|
| 回环 | 无 | `loopback_direct` | 免令牌**前提**（还需 `LG_LOCAL_BYPASS=1` 才真免） |
| 回环 | 有 + peer 命中白名单 | `trusted_proxy` | **需令牌** |
| 回环 | 有 + 未命中 | `untrusted_proxy` | **需令牌** |
| 非回环 | 任意 | `remote` | **需令牌** |

`_is_local` 改成同一结论的另一种写法，口径**逐字对齐 1.2**，没有放宽：

```python
def _is_local(request: Request) -> bool:
    return access_route(request) == "loopback_direct" and local_bypass_enabled()
```

即「`loopback_direct` 是免令牌的唯一入口」这条不变量由**等值比较**机械保证，
不是靠注释约定（回归里穷举验证，见 ③ 的 `test_whitelist_can_never_widen_bypass`）。

### 2.2 可信代理白名单 `LG_TRUSTED_PROXIES`（新增 env，默认空 = 最严）

- `trusted_proxies()`：逗号分隔逐项 strip，**空项丢弃**（不产生「空串匹配一切」的口子），
  未设 ⇒ `()`。每次调用现读环境（与 `local_bypass_enabled` 同协议，测试可 monkeypatch）。
- `_parse_trusted_proxies()`：把声明条目拆成 `(合法条目, 非法条目原文)`；非法条目**剔除不放行**，
  原文带回供自检点名（拼错的 IP 被静默忽略，正是要消灭的那类「看起来配了其实没生效」）。
- `peer_is_trusted_proxy(host)`：单 IP 精确匹配 / CIDR 包含；peer 是主机名或怪值 ⇒ `False`（fail-closed）。
- **白名单不参与放行**：`trusted_proxy` 与 `untrusted_proxy` 同样要求令牌。白名单买到的只有
  ①响应头 `X-Access-Via` 上的可观测标签，②自检里「这条流量确实来自你声明的代理」这一行核对文字。
  写 `0.0.0.0/0` 进白名单也放不开带代理头的请求（回归已钉）。
- 没有任何 env 能把「需令牌」翻成「免令牌」；`LG_LOCAL_BYPASS` / `REVIEW_NO_AUTH` 语义一字未改。

### 2.3 `self_check()` 可机械核验（原样打印，不许折叠）

新增两块输出：

1. `LG_TRUSTED_PROXIES=` **原样取值**，未设时打印字面量 `(未设)`（不折叠成「无」之类说法），
   并附「声明 N 条 / 合法 M 条 / 非法忽略 K 条」，非法条目逐条点名。
2. 「代理头出现时的判定结果」用真实回环 peer **实算**成一行文字（不是模板字符串）：
   带代理头 ⇒ `via=?`；无代理头 ⇒ `via=?`；非回环 peer ⇒ `via=?`；白名单是否覆盖该 peer。
3. 若 `LG_LOCAL_BYPASS=1` 处于开启，额外喊出风险面提示（回环代理漏传头 ⇒ 整站免鉴权，
   并指向绑定面 `0.0.0.0`）。

### 2.4 运行时可观测：`X-Access-Via`

`install()` 里门自己产出的四类响应（302 换 cookie / 401 门页 / 403 档位不足 / 各自带标签）
统一由 `_tagged(resp, route)` 打标签。标签**只在判定之后回显结论**，不参与判定，
故加与不加不改变任何一格放行结果；不回显 peer、不回显令牌。

## ⑤ 遗留与风险

1. **线上代理是否真的漏传头：未核实**。本任务只做收口与可验证，不含「已被利用」的断言，
   也未探测任何线上端点。部署方核对路径：看启动自检那一行 `代理头判定（回环 peer 样例 …）`，
   再用手机/外网打一次带 `CF-Connecting-IP` 的请求，核对响应头 `X-Access-Via` 是否为
   `trusted_proxy`/`untrusted_proxy`（而非 `loopback_direct`）。若期望标签是 `trusted_proxy`
   却拿到 `untrusted_proxy`，说明 peer 不在 `LG_TRUSTED_PROXIES` 里。
2. **「漏传头」仍是唯一残余风险面，且只能靠显式开关守住**。改前改后都成立：回环代理若**完全不传**
   三个代理头中的任何一个，请求就落 `loopback_direct`；此时是否免令牌取决于 `LG_LOCAL_BYPASS=1`。
   本次**没有**（也不该）新增「默认拒绝回环直连」的口子——那会破坏既有本机直连用法。
   实际缓解手段仍是：不设 `LG_LOCAL_BYPASS`（默认），或把绑定面从 `0.0.0.0` 收到 `127.0.0.1`。
3. **`serve_remote.sh` 未改**（不在允许编辑范围）。`--host 0.0.0.0` 依旧是有意暴露；
   脚本第 162 行已自行打印绑定面提示，与应用侧自检互补。
4. **白名单条目只接受 IP / CIDR，主机名永不匹配**（fail-closed）。`LG_TRUSTED_PROXIES=localhost`
   不会命中 peer `localhost`——`ipaddress.ip_address` 解析失败即视为不在白名单内。
   这是收紧方向的选择，代价是「想用主机名声明代理」的部署方会得到 `untrusted_proxy` 标签；
   自检会把无法解析的条目逐条点名，不静默。
5. **`localhost` 作为回环写法本身有绕过面**：`_LOCAL_HOSTS` 含字符串 `localhost`，
   判定是精确字符串比较，未做反向 DNS 归一。此为**改前既有**口径（本次未动、未放宽），
