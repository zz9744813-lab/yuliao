## 1. 离线复现（零配额）

### 1a. 缺省夹具不触发 s2 失败（如实记录）

```
LG_DATABASE_URL=sqlite:///F:/agi/language-genome/data/language_genome.db \
F:/Hermes/hermes-agent/venv/Scripts/python.exe scripts/k4_paired_scenes.py \
  --scenes 3 --out F:/agi/_scratch/k4s2_base
→ exit 0；prose 6/6 committed（s1/s2/s3 × A/B）；failures=[]；skipped=[]
```

**结论：离线默认 FixtureClient 路径不触发 s2 失败**。原因（读码可核）：
FxClient 的 verifier 恒判 issues=[]（scripts/k4_paired_scenes.py 的
FxClient verifier 分支），第一轮即收敛，每场每臂只用 2 次调用——
真跑 s2 的失败由 deepseek writer/verifier 的**内容输出**（三稿不满足
计划事件/状态契约、核验工件返修）驱动，预算闸与改稿轮是被动的计数方。

### 1b. 驱动层离线复现两个失败「形」（同闸码，零配额）

用 verifier 恒判 hard issue 的离线客户端（`_NeverPassVerify`，tests/
test_k4_paired.py），经**驱动器自身的 except 路径**落账：

- 缺省预算 6：writer.0/verifier.0 → writer.1/verifier.1 → writer.2/
  verifier.2 共 6 调用 → 改稿轮 `range(max_rewrites+1)` 用尽 →
  **`rewrite_budget_exhausted:<errors>`**（s2-B 同形同机制；错误清单
  内容为离线夹具的 unresolved_hard_issue，live 的三条由真稿内容决定）；
- 预算 2：writer.0/verifier.0 两调用后第 3 次调用被 store 的预算闸拒 →
  **`call_budget_exhausted`**（s2-A 同形同机制）。

两形态均已在 `test_budget_calls_configured_effective_and_actually_used`
（钉②）中以断言复现，断臂/skipped 连锁随失败如实出现。

## 3. 最小修复（默认语义零变化是硬约束）

改动只在 `scripts/k4_paired_scenes.py` + `tests/test_k4_paired.py`（未动
`app/scene_runtime` 语义、未动契约、未动 K2/K3 判定口径）：

1. **`run_paired(..., budget_calls: int | None = None)`**：缺省走
   `Budget()` 无参构造——与现状**逐字一致**；显式传参走
   `Budget(max_calls=N)`（仍受契约 ge=2/le=20 约束）。
2. **生效值写进收据**：每条 receipt 新增 `budget_calls` 键（缺省=6）。
3. **CLI 入口** `--budget-calls N`：域校验 [2,20] 与契约同口径（1/21 拒），
   缺省不带参数＝现状。
4. **预算耗尽失败诊断** `budget_diag`（仅预算类失败记录新增，其余失败
   记录逐字不变）：`max_calls`（生效上限）/`configured`（是否显式传参）/
   `actual_calls` / `failed_calls` / `repair_calls`（.contract1/.state1/
   .retry 段计数）——从本臂**世界产物库**（临时 sqlite，只读 SELECT）取数，
   给 `scripts/k4_accept_report.py` 的机械判据补硬证据。**不改变判定**：
   预算耗尽仍按失败记账，绝不改判通过。

s2-B 根因（writer 场景契约遵从）：诊断与提案只在本文档——不改
`app/scene_runtime` 语义。提案：live 跑前把 plan 事件/changes 摘要显式
注入 writer system 指令，或按 docs/K4验收定性_20260925.md §3 由主控
拍板换 writer 模型（动模型基线须按 C5 标记并复核）。
