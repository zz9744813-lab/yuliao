# 提案：按 corruption_type 强制 50/50 长度方向重生成（bal-v2 管线）

> 2026-09-20 · 只读分析，未改数据、未发 LLM 调用。
> 背景：`docs/corruption-length-audit-20260920.md` §7 实证劣化生成长度方向几乎单边
> （三集合非等长题里 human 更短占 .917/.944/.867），
> Gate 分档后档一只认长度平衡基准（bal-v1，仅 38 题），L 侧库存全库只有 19 对——
> 不重生成，档一永远不可判定。

---

## 0. 为什么库存配平不可行（先把这个否掉）

- 基准段合格对 219 中 human 更长仅 **19 对**，且集中在 LITERARY_OVERWRITE(8)/
  NEUTRAL_PARAPHRASE(6)/PARALLELISM_OVERUSE(3)/RHYTHM_FLATTEN(1)/
  DIALOGUE_EXPOSITION(1)——其中 6 对还是控制臂（判别题合法但语义特殊）。
- 放宽到**全部段**（不限基准段、不限 src_ok）也只有 ~52 对，且其中一部分
  挂在坏源/番外段上，真正可用增量不足 30。
- bal-v1 已把 19 对全用上（n=38）——判定 weak（0.737，超长度基线 p=0.078，
  **差一个样本量**就到显著）。继续在库存上配平没有任何余量。
- 结论：**必须重生成**。目标：L 侧（human 更长）每类型 ≥10 对，总量 ≥200 对。

## 1. 最小改动面（全部复用现有管线）

现有资产已够：`scripts/controlled_corruption.py` 的 18 类单变量生成 + drift
校验（`len_ratio` 字段已记录、`rejected_length` 状态已存在、病句硬拒 +
`mechanical_defect()` 确定性兜底在 09-18 已加固）。

| # | 改动 | 位置 | 内容 |
|---|---|---|---|
| 1 | **TYPE_LEN_SPEC 表** | controlled_corruption.py | per-type 目标方向（`L`=variant 更短 / `S`=variant 更长 / `any`）+ 接受窗：L 类 `len_ratio∈[0.60,0.92]`，S 类 `[1.08,1.80]`（现有全局长卡 0.55~1.8 收紧而来） |
| 2 | **生成 prompt 加长度指令** | 同上，per-type 模板 | 压缩型加一行「改写后总字数必须压到原文 60%~90%」；病句硬拒**不变**（长度约束不得污染语法质量——§7.7 的教训是双向的） |
| 3 | **verify 并窗** | 同上 `judge_verify` | 方向/比例越界 → `rejected_length`（现有状态，零新枚举） |

- **12 个膨胀型**（EXPLICITIZE/ADJECTIVE_INFLATION/REDUNDANCY/…）天然产
  S → 保持 `any` 窗即可（它们是 S 侧的既有来源）。
- **6 个压缩型**（SUBTEXT_ERASE/ABSTRACT_SUMMARY/RHYTHM_FLATTEN/
  LITERARY_OVERWRITE/EMOTION_LABEL/DIALOGUE_EXPOSITION）→ 指定 `L` 窗。
  注：LITERARY_OVERWRITE 是唯一实测有真信号的类型（Δ+41.7pp，两侧≥0.6），
  它的 L 侧扩产优先级最高。
- **不需要**新表、新字段：`len_ratio`/`drift`/`status` 全在；`BenchmarkSet.spec`
  已有 `"balanced"` 键；`benchmark_build.build_length_balanced` 已按方向分桶消费。
- 下游全复用：生成 → 校验 → `build_length_balanced`（改个 per_side 上限）→
  `benchmark_run` → `benchmark_falsify`（N4 长度基线 / N5 分层判定已在）。

**预算量级**：L 侧 200 对 ≈ 生成 200 + 校验 200 ≈ 400~500 次中转调用
（deepseek-v4.1-flash 单模型约 1~2 小时；校验建议仍用第二家防自证）。

**产出率预案（强制窗的通过率不能盲赌，会审补充）**：先跑 **20 对 pilot**，
统计窗口接受率；**≥30% 才转正式批**，否则窗口各放宽 ±0.05 再 pilot 一次
（最多两轮，仍 <30% 的类型记"本代模型不可产出"并在提案附表留档，
不烧正式预算）。回归测试补 per-type 窗口边界用例（恰在 0.60 / 0.92 /
1.08 / 1.80 的样本与越界拒收），沿用 09-18「病句硬拒」加固的测试形状。
段源：用**新段或未冻结段**（EXP-0919-SCALE* 已补 202+202 帧，池子健康），
§14 冻结条目一律不动。

## 2. 兼容路径：新集（bal-v2），不就地补题

- **就地补题 = 换题面**：benchmark_items 冻结文本是 §14 跨时间可比的根基，
  往 cc-v1/nat-v1 里掺新题等于让历史读数失去对照——否掉。
- bal-v2：`kind='length_balanced'`，`spec` 带 `split=2` 版本标记
  （会审 qwen 意见：采样宇宙变化必须带版本，否则同 seed 不可复现）。
  bal-v1 原样保留，作为 38 题时代的留档读数。
- **迁移代价：零代码迁移**。只有生成 + 建集 + 跑分的调用成本；
  排行榜/`benchmark_falsify` 对新 kind 自动生效，无需改判定逻辑。

### 2.1 双集消费契约（同 kind 并存的场合，会审补充）

所有下游消费者都按 **set_id** 寻址（falsify / benchmark_run / 排行榜），
双集并存本身无歧义；唯一的跨集读取点是 final_report 的档一查询——契约
已固化为「**先取最新创建的 split，再在该集内取最高分**」（跨集挑最高分
= 樱桃采摘，已随本提案一并修掉，`d76fca2`）。`build_length_balanced`
的幂等键是 set 名（bal-v2 ≠ bal-v1），不互踩。
