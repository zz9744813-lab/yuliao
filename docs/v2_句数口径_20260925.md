## 2. 修法与同源依据

### 2.1 口径链路（不自写第三套切句器）

`scripts/import_corpus_v2.py` 新增唯一入口 `n_sents()`（第 49–58 行），建段处
第 196 行由 `n_sentences=0` 改为 `n_sentences=n_sents(ch)`：

```python
def n_sents(text: str) -> int:
    """本脚本唯一的句数口径入口。…"""
    return segmenter_v2._count_sents(text)
```

链路：`import_corpus_v2.n_sents` → `app/segmenter_v2._count_sents`
（`app/segmenter_v2.py:158–159`）→ `app/metrics_det._sentences`
（`app/segmenter_v2.py:21` 就是 `from .metrics_det import _sentences`）。
v1 路径 `app/corpus.py:21` import 的也是同一个 `_sentences` ⇒ **两条导入路径同源**，
不是「两套实现碰巧一致」。

`_count_sents(t)` ≡ `len(_sentences(t))`（前者只是把后者的结果再过一次
`strip` 过滤，而 `_sentences` 已滤空），所以选它不会引入任何计数偏移；
回归里用 `test_count_sents_is_the_v1_metrics_impl`（7 组样本参数化）把这条恒等式钉住，
并用 `test_v2_import_matches_v1_import_file` 在**落库层**证明 v1 `import_file` 与 v2 导入
对同一文本逐段同句数。计数对象是 `text` 原文（与 v1 一致），`text_clean` 不参与。

### 2.2 口径入口缺口（如实记）

而本席被禁止改 `app/`。现状＝工席脚本引用上游私有函数（上游内部本来也这么互引）。

最小建议（交主控拍板，本席未做）：在 `app/metrics_det.py` 导出

`app/corpus.py:180–183`、`app/segmenter_v2.py:158`、`scripts/import_corpus_v2.py`
三处一律改调该公开口——把「同源」从约定升级成编译期单点。

v2 导入口径随之变更，**不得**在 `import_corpus_v2.py` 里加规则或另抄正则
（`test_n_sents_delegates_to_segmenter_v2` 会在有人另抄时立刻打红）。

### 2.3 补数脚本 `scripts/backfill_v2_sentences.py`

- **默认 dry-run**：不加 `--apply` 时只读，报 `would_update` 与抽样 `n_sentences 0 → N`，
  一次 commit 都不发（代码里 dry-run 分支根本不赋值，另加 `expunge_all()` 丢弃身份映射）。
- **只有显式 `--apply` 才写库**；每次启动先打印目标库 URL 与模式，避免误指真库。
- **幂等**：过滤器只取 `n_sentences == 0` 且 `text.strip()` 非空的段；该口径对任何
  非空文本恒 ≥1，补完即不再命中；空文本段保持 0（如实反映「没有句子」），
  原本非 0 的行一律不动。重跑输出 `updated 0`。
- **分批提交**：批量默认直接取 `import_corpus_v2.BATCH`（模块加载时读现值，不另立数字），
  按主键 keyset 分页（`id > 上一批末 id`），42 万行不一次 commit、不整表进内存。
- **范围可控**：`--work WORK_ID`（可重复）只补指定书，便于先在真库拿一本试点书看影响面。
- 口径同样**单源**：脚本不自己数句子，而是 `IC.n_sents`（`_import_mod()` 加载
  `scripts/import_corpus_v2.py` 取函数与 BATCH）。
