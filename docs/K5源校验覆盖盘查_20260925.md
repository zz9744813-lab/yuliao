## 4. 口径影响（真跑 SQL）

「保持未校验」= 不补跑、库里一个字都不改：口径 A/B 的谓词作用在现状数据上，成员判定逐段独立，未校验段的存量状态不变⇒ 两口径读数不变（实测即现值：A 松 4,220 / A 严格 4,220 / B 401,611）。细分：missing/nojson 段结构性不满足 `IS TRUE`；loose 段中数字 1 这类脏值**会**漏进松口径 A——「未校验 ∧ A」实测 0（其中脏值掺水即 leak），而严格布尔口径下恒 0。口径 B 不消费 src_ok，未校验段本就已按其自身条件计入/排除（「未校验 ∧ B」= 395,648 为 B 池内可补查量）。补跑 source_check 才可能改变 A/B；不补跑则纹丝不动。

- 现值：口径 A（松 IS TRUE）= 4,220；口径 A（严格布尔）= 4,220；口径 B = 401,611。
- 「未校验 ∧ A」= 0；「未校验 ∧ B」= 395,648。
