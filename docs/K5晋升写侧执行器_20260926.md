## 1. 硬契约落点（逐条对应）

### 契约 1：默认 `--dry-run`，不带 `--commit` 零写入

- 判词路径与写路径分离：`build_report()` 全程只经 `open_ro_session()`（`mode=ro`），
  `--commit` 才调 `_execute_commit()` → `commit_promotion()`。
- 报告里 `discipline.db_writes_during_judgement == 0`、`discipline.planned_writes == 0`
  （dry-run 档）/ `== 1`（commit 档，仅"计划"数）。
- 测试：`test_dry_run_is_default_and_writes_nothing`、`test_dry_run_is_the_default_mode`、
  `test_judgement_leaves_db_and_directory_untouched`。
- 真库实跑前后 md5 一致（§3）。

### 契约 2：证据为空必须拒绝 —— 退出码 2 + stdout 含字面量 `NO-PROMOTE`

- `EXIT_REFUSED = 2`；`NO_PROMOTE = "NO-PROMOTE"`（模块级常量）。
- 拒因字面量**不自己写**：证据为空的拒因 `excluded_no_evidence` 直接取自
  `GE.explain_strategy()` 的 `gate3_evidence` 判词（判据单源）。
- **`--dry-run` 判词与真写判词一致**：两者都只经 `evaluate()` 这一个函数，
  渲染只有一个点 `line_of()`，不存在两条分支各写一套。
  测试 `test_verdict_line_identical_between_dry_run_and_commit` 断言
  `[v["line"] for v in dr] == [v["line"] for v in cm]` **逐字节相同**。
- 测试：`test_empty_evidence_refuses_exit2_with_literal`（dry-run 与 commit 两档
  都断言 `== 2` 且 `reason=excluded_no_evidence` 与 gate3 逐字相等）、
  `test_commit_recheck_prints_the_same_line`（真写前复检判词 = dry-run 判词）。

### 契约 3：单事务 —— status 变更 1 行 + 审计行 1 行，任一步失败整体回滚

- `commit_promotion()`：`BEGIN IMMEDIATE` → CAS `UPDATE`（`WHERE id=? AND status=?
  AND observation_status=? AND scope=?`，断言 `rowcount == 1`）→ `INSERT` 审计行 →
  `COMMIT`；`except` 分支 `ROLLBACK` 后 `raise`。
- 两条中途异常路径都有测试：
  - `test_rollback_when_audit_replay_collides`：同一次变迁重放撞审计主键
    ⇒ 两表整体回滚（策略行与审计行都还原）。
  - `test_rollback_when_cas_guard_sees_zero_rows`：CAS 旧值失配（`rowcount=0`）
    ⇒ `PromotionGuardError` + 整体回滚。
- `test_commit_changes_exactly_one_row_and_one_audit`：成功路径恰好 1 行 status + 1 行审计。

### 契约 4：禁跳级 —— 只允许逐级，跳级必须被拒并给可读原因

- 阶梯 `LADDER = (hypothesis, observed, replicated, verified)`；
  `ti - li > 1` ⇒ `refuse("skip_ladder:{level}->{requested}（跨 N 级，禁跳级）", list(LADDER[li+1:ti]))`
  —— 原因里**点名被跨过的级**。
- 同层 `no_step`、降级 `not_promotion`、顶 `already_top`、契约外取值 `off_ladder`
  均被拒。
- 测试：`test_skip_ladder_refused_with_skipped_rungs`、
  `test_same_level_and_demotion_and_off_ladder_target_refused`、`test_top_of_ladder_refused`、
  `test_full_ladder_walk_ends_k3_eligible`（逐级走完全程）。

### 契约 5：审计行不可变 + 只读校验

- 审计表 `AUDIT_TABLE` 含 `from_status`/`to_status`/`evidence_ref`/`ts` 等列
  （`AUDIT_COLUMNS`）。
- 只读校验函数 `verify_promotion_audits()`（fail-visible：坏行报出来，不静默）。
- 不可变靠两道：DDL 侧 `test_audit_table_blocks_update_and_delete`（触发器阻断
  UPDATE/DELETE），源码侧 `test_no_update_or_delete_code_path_on_audit_table`
  （扫描源码确认无 UPDATE/DELETE 审计表的代码路径）。
- 审计主键 `audit_id_for()` = 变迁负载规范化哈希 ⇒ 同一次变迁重放天然撞键。
