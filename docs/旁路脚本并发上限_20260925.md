## 1. 改前复现（离线、不起真线程）

### 1.1 复现方法

只用 AST 从 **基线 `d3f4954` 的源码**里提取两处真实定义——`add_argument("--conc", …)`
与 `ThreadPoolExecutor(max_workers=EXPR)`——再对 EXPR 以 `conc=200` 求值。
零模型调用、零线程、零网络。驱动脚本（本会话已实跑，见 §1.2；基线源码经
`git show d3f4954:<path>` 读取，**不碰工作区任何文件**）：

```python
# -*- coding: utf-8 -*-
"""改前各旁路脚本 --conc 200 时实际会开的 worker 数（离线复现）。"""
import argparse, ast, subprocess
from types import SimpleNamespace

def baseline(rel):  # 读基线源码，不碰工作区
    return subprocess.run(["git", "show", f"d3f4954:{rel}"],
                          capture_output=True, text=True, encoding="utf-8").stdout

def add_argument_call(ap, node):
    # ast.unparse 整棵 Call 会带 `ap.` 前缀（变成 ap.ap.add_argument），
    # 必须逐参数重建；见第一次实跑踩坑记录（§5.2）。
    parts = [ast.unparse(a) for a in node.args]
    parts += [ast.unparse(k) for k in node.keywords]
    eval(f"ap.add_argument({', '.join(parts)})", {"ap": ap})

TARGETS = {
    "scripts/clean_text.py":      "conc",
    "scripts/backfill_judges.py": "args",
    "scripts/dim_probe.py":       "args",
    "scripts/extra_judges.py":    "args",
    "scripts/source_check.py":    "conc",
}
for rel, ns_name in TARGETS.items():
    tree = ast.parse(baseline(rel))
    add_def, exec_exprs = None, []
    for n in ast.walk(tree):
        if isinstance(n, ast.Call) and getattr(n.func, "attr", "") == "add_argument" \
                and any(isinstance(a, ast.Constant) and a.value == "--conc" for a in n.args):
            add_def = n
        if isinstance(n, ast.Call):
            f = getattr(n.func, "id", None) or getattr(n.func, "attr", None)
            if f == "ThreadPoolExecutor":
                for kw in n.keywords:
                    if kw.arg == "max_workers":
                        exec_exprs.append((n.lineno, ast.unparse(kw.value)))
    ap = argparse.ArgumentParser(); add_argument_call(ap, add_def)
    got = ap.parse_args(["--conc", "200"]).conc
    ns = {"conc": got, "args": SimpleNamespace(conc=got)}
    print(f"== {rel}: argparse 接受 --conc 200 -> conc={got}（无上界校验）")
    for lineno, expr in exec_exprs:
        print(f"   :{lineno} max_workers={expr} -> 实际 worker 数 = {eval(expr, ns)}")

# 两个 config 写入方：不自建池，argparse 无上界即越界值落库/下传
for rel, flag, note in (
    ("scripts/scale_corpus.py",  "--conc", "越界值随后写 exp.config['concurrency'] 落库 + 下传 source_check.run"),
    ("scripts/run_calibration.py", "--concurrency", "原样写 overrides 落库"),
):
    tree = ast.parse(baseline(rel))
    for n in ast.walk(tree):
        if isinstance(n, ast.Call) and getattr(n.func, "attr", "") == "add_argument" \
                and any(isinstance(a, ast.Constant) and a.value == flag for a in n.args):
            ap = argparse.ArgumentParser(); add_argument_call(ap, n)
            got = getattr(ap.parse_args([flag, "200"]), flag.lstrip("-").replace("-", "_"))
            print(f"== {rel}: argparse 接受 {flag} 200 -> {got}（{note}）")
            break
```

## 3. 为什么 CLI 越界是「响亮报错退出」而不是静默 clamp

- 命令行的数值是操作者**亲手声明的意图**。静默改写会让人「以为在 200 并发、实跑 16」：
  对费用、限速与排期护栏而言，**意图错位比失败危险**——失败会重跑，错位产出的数据
  带着错误前提进分析。要更高并发，唯一路径是改真源 `app/limits.py` 并重新定价，
  不是往命令行塞数字。
- 与上一轮口径一致：HTTP 入口拒绝 422（`app/experiments`），执行中兜底截断且**记录**
  （`concurrency_clamped_from`）；同理，写库前的 config 必须已是合法值，否则事后审计
  会把「被兜底跑 16」的实验误读成「操作者要 200」。
- 运行时函数入口（别处 import 直调）没有「意图」可尊重，才用 clamp + **显式打印**
  `[conc] 越界截断`（不静默）；这条路径由回归测试用替身钉死。
