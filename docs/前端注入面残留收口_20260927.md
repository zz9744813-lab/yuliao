## ① 出口逐条盘点（行号 = 本轮改动后的最终态）

上下文图例（本轮对**每个插值点**统一判到这三类之一）：

- **文本上下文** = 标签与标签之间的文本位；插值即字符数据，转义 `& < > " ' `` ` `` 即闭合。
- **属性上下文** = 拼进 HTML 串的双引号属性值位（`value="…"` / `data-*="…"` / `title="…"`）；
  这里 `escHtml` 的引号转义在语义上已够，但本轮统一收口为专用 `escAttr`，
  使「属性位」与「文本位」的转义口径在代码里显式可审计（见 ②-1）。
- **类名或样式上下文** = `class="…"` / `style="…"` 的值位。**转义救不了这里**：
  属性分词靠空格/分号，`"` 转成 `&quot;` 之后 payload 里的空格、`.`、`{`、
  事件属性名仍可存活并起效，所以本轮一律走白名单（`escClass`）或 DOM 赋值。

「上下文」列在下表中一律用上面三个全称，不做缩写，以免把属性上下文与
类名/样式上下文混读（上一版图例用「属性」「类名/样式」两个短词，正是本次
复核门打回的原因之一）。

### 为什么属性上下文/类名位的收口用 `escAttr/escClass` 而不是全部改 DOM（任务条款二选一的理由）

- `showExp` / `loadCorpus` / `loadDoneList` 的**函数源码切片**被 `test_frontend_escape`
  用「无 `document` 的 node stub + 断言 `innerHTML` 含转义实体」执行（本轮不得改该文件），
  改 DOM 构造会直接推翻既有测试；
- `composeHtml`/`buildMarkedHtml` 是返回字符串的纯函数，偏移契约（剥标签逐字相等）
  由 `test_diff_js` 钉死，无 DOM 可用；
- 任务条款允许「提供 `escAttr` 并**只**用于属性位置」这条路，且类名位另给了白名单口径。
  本轮照此执行，`escAttr` 全部出现点被新测试静态钉在 `="…"` 属性位内
  （`test_escattr_defined_and_used_only_in_attribute_positions` 逐点断言其前缀是 `="`）。
  纯浏览器路径（`loadExps`）则按条款另一路走 DOM 构造，未回退。

1. **属性上下文仍是字符串拼接**：`data-mid`/`title`（index.html:1161、diff.js:158–161）
   维持 escHtml 口径——被 `test_frontend_escape` 逐字钉死且 composeHtml 有字符串返回
   契约；双引号属性内引号已实体化（`"`→`&quot;` 无法闭合属性），判定为「已闭合的
   属性上下文」，但不是 DOM 构造，也未统一到 `escAttr` 口径（与 ②-1 的差异是
   缺反斜杠项 `&#92;`；双引号属性值里 `\` 无转义语义，实测不构成挣脱）。
   彻底 DOM 化需要连任两轮测试的锚点一起重做，超出本轮可改文件范围。

   值，类名会退化为粘连 token（仅失去 CSS 着色，不产生安全问题）；文本位显示不受影响。
3. **`showSkeleton` 的 `style="width:${w}%"`**（881）：`w` 目前是数字字面量形参，
   非服务端数据，未收口；若有人把外部值接进 `line()` 即成为样式注入面——新测试的
   全文 `style="…${esc…}` 扫描不覆盖裸变量插值，靠代码评审兜底。
4. **`#rv-exp` 无动态用例**：`initReview` 依赖过多全局（渲染链 + 取题链），node stub
   过脆；其 value 属性收口由静态逐字钉 + `escAttr` 单元行为覆盖。
5. **fetch URL 查询拼接**（如 `?batch=${BATCH}&ctx=${CTX_SCOPE}` 等）属请求面不属
   HTML 注入面，本轮范围外；`curExp` 等是否需 URL 编码建议下轮连同服务端入参校验一起看。
6. **`app/static/console.html:218/240`** 存在同形态（数据拼 innerHTML），不在本轮
   允许编辑清单内，未动——遗留。
