## 1. OPEN-5：外部 `LG_LOCK_DIR` 炸掉 `test_live_guard.py` 全文件

### 1.1 机理（与代码对应）

`tests/test_live_guard.py` 顶部 autouse 夹具 `_isolated_lock_dir` 原先只用
`monkeypatch.setattr(config, "DATA_DIR", tmp)` 改锁位；而
`app/live_guard.lock_path() → config.live_lock_path()` 里
**`LG_LOCK_DIR` 环境变量的覆盖优先于** 进程内 `DATA_DIR`
（`app/config.py:41-43`）。外部设了该旋钮时，夹具改的 `DATA_DIR` 被 env 覆盖
短路，`lock_path()` 仍指覆盖目录——而 `tests/conftest.py` 的整轮 pytest 锁
（purpose="pytest"）恰好也持在同一覆盖目录（`prod_lock_path()` 同跟随该旋钮），
夹具前置断言 `LG.live_run_active() is None` 即失败 ⇒ **setup 阶段炸掉全文件**。

### 1.2 修复（`tests/test_live_guard.py`）

- 夹具内先 `monkeypatch.delenv("LG_LOCK_DIR", raising=False)` 再覆写 `DATA_DIR`
  （与 `test_live_guard_deadpid.py` 既有夹具同口径——该文件早已 delenv，
  故 11 errors 只炸 `test_live_guard.py` 一个文件）。
- 模块导入期采集 `_ORIG_LOCK_DIR_OVERRIDE`；
  `test_refuse_default_watches_prod_path_not_test_dir` 仅当本轮在外部
  `LG_LOCK_DIR` 覆盖下启动时 `pytest.skip`——该用例钉的前提「conftest 整轮锁
  持有在 ROOT/data 生产位」在覆盖口径下**事实不成立**（锁随旋钮走了），
  硬跑只会假红。**既有断言一字未放松**；覆盖口径的不变式（一个旋钮两侧同跟随
  / 生产位不随 `LG_DATA_DIR` 漂移）由在册
  `test_live_guard_mutex.py::test_lock_path_single_source_exported_by_config`
  钉死，两不遗漏。

### 1.3 承重变异与反向验证（必做项，本通道亲手跑）

对夹具修正做**回退变异**（删去 `monkeypatch.delenv("LG_LOCK_DIR", ...)` 一行），
验收门 2 必须转红；恢复后复绿且 md5 一致：

| 步骤 | 命令（§3.2 门 2 同一条） | 读数 |
|---|---|---|
| 变异前（修复在位）基线 md5 | `md5sum tests/test_live_guard.py` | `5b86810ff28ca346322b24c6d0b590b2` |
| **反向验证**（回退变异后跑门 2） | 同 §3.2 | **rc=1**，`grep -c "^ERROR tests/test_live_guard.py"` = **11** |
| 恢复后 md5 | `md5sum tests/test_live_guard.py` | `5b86810ff28ca346322b24c6d0b590b2`（**与变异前逐字一致**） |
| 恢复后再跑门 2 | 同 §3.2 | **rc=0**、0 ERROR（30 passed + 1 skipped） |

⇒ 该 delenv 一行**承重**：删则 11 errors 复现，有则 0 error；不是装饰性代码。

## 2. OPEN-4：裸跑在源检出里创建 `data/` 的副作用

### 2.1 复现（修复前，本通道亲手跑）

在干净 worktree `F:/agi/_scratch/worktrees/r6-open45`：

```
F:/Hermes/hermes-agent/venv/Scripts/python.exe -m pytest tests/test_live_guard.py -q -p no:cacheprovider -k child_probe
⇒ rc=5；收工后检出目录多出 data/（空目录，live_run.lock 已随 sessionfinish 释放被删）
```

如实注记：本 worktree 的 `.gitignore` 第 2 行含 `data/`，故此处
`git status --porcelain` **不显示** `?? data/`（与主控在另一形态检出上实测到的
`?? data/` 读数不同版式；主控那条读数为**未自跑**——差异仅在 gitignore 是否覆盖
`data/`，「裸跑创建 data/ 再删锁留空目录」的副作用本身已逐字复现）。

### 2.2 修复（判据 a + b 双落地）

`tests/conftest.py`：

- **判据 a（响亮 warning）**：`pytest_configure` 在取锁**之前**判定
  「`LG_LOCK_DIR` 未设 且 `ROOT/data` 原本不存在」→
  `config.issue_config_time_warning(UserWarning(...))`，文本含字面量
  `OPEN-4` 与 `LG_LOCK_DIR` 和「建议跑套件前设 `LG_LOCK_DIR=<临时目录>`」。
  实测该通道在 `-q` 下也进 `warnings summary`（见 §3.3 输出原文）。
- **判据 b（不留副作用）**：同判定处记下「本轮创建的锁目录」，
  `pytest_sessionfinish` 释放整轮锁后 `rmdir()`——**只删空目录、只删本轮
  自己创建的**；非空（他人产物/并发会话）或已被删 → `OSError` 吞掉、原样
  保留，绝不递归删。`LG_LOCK_DIR` 显式覆盖时整条逻辑不触发（锁位本就在检出之外）。
- **回归**：`tests/test_live_guard_mutex.py::test_open4_bare_pytest_warns_and_leaves_no_data_dir`
  ——把 `app/`＋`tests/conftest.py` 复制进 tmp 仿造根，子进程真跑裸 pytest
  （`config.ROOT` 随复制位置漂移，**不触本仓真实 `data/`**），断言
  ① 输出含 `OPEN-4` 与 `LG_LOCK_DIR`（warning 文本可断言到＝判据 a 达成）；
  ② 该轮 `1 passed`、rc=0（warning 不改变结果）；
  ③ 收工后仿造根里 `data/` 不存在（判据 b 机理同款）。

## 4. 如实声明：亲手跑 vs 静态推演 vs 未自跑

**本通道亲手跑（本文所有引用读数均出自实跑日志）**：门 1×2、门 2、门 3；
OPEN-5 修复前 11-ERROR 复现与回退变异-复现-恢复-md5 闭环（§1.3）；OPEN-4
副作用复现（修复前 data/ 空目录残留）；新回归 `test_open4_bare_pytest_warns_and_leaves_no_data_dir`
（含在门 1/门 2 的 31 用例内，两条门均绿）；`pytest tests -q` 全量套件一轮
（见下条环境性红的甄别）。

**环境性既有事实（非本批引入）**：全量 `pytest tests -q` 在本干净 worktree 有
若干红（`sqlite3.OperationalError: no such table: candidates` 等），失败点均为
测试直连 `ROOT/data/language_genome.db`（本检出无真实数据库）；单独隔离跑同一
用例仍同样失败，与本批 conftest/夹具改动无关。本批验收门只划 3 个守卫文件。
全量跑另会在 `data/` 留下 0 字节 `language_genome.db`——该目录因此「非空」，
OPEN-4 收尾 rmdir 按设计**不**强删（宁留勿删），已人工清回原状。

**未自跑（如实挂账，命令留给主控）**：
- 主控侧「`git status --porcelain` 出现 `?? data/`」的读数形态：本 worktree
  `.gitignore` 含 `data/`，此通道实测为「data/ 目录存在但不被 git 报出」。要在
  源检出里机械看到 `?? data/`，需在 gitignore 未覆盖 data 的检出跑
  `PY -m pytest tests/test_live_guard.py -q -p no:cacheprovider -k child_probe`
  再 `git status --porcelain`——**未自跑**（修复后两种形态都不再残留 data/ 目录本身）。
- Windows 断电/硬杀下 OPEN-4 收尾 rmdir 不执行（atexit 也不补 rmdir）时
  `data/` 空目录残留：静态推演（进程被 SIGKILL/taskkill /F 时 sessionfinish
  不跑），未做破坏性实验；守卫互斥语义不受影响，仅目录卫生。
