# 旁路脚本并发闸第二批（2026-09-25）

## 0. 结论

本批收口 12 个旁路脚本的线程池入口：`source_check`、`benchmark_run`、
`frame_violation`、`heldout_eval`、`overexplain_probe`、`pref_judge`、
`prerun_batch_judges`、`span_probe`、`xcorpus_bias`、`run_nat_v2`、
`controlled_corruption`、`ai_ranking_build`。

统一规则如下：

- CLI 并发值在进入数据库、预检或网络前调用 `check_conc`；上界和下界越界均通过
  `parser.error` 响亮退出，退出码为 2，不静默 clamp。
- 所有线程池的 `max_workers` 都来自共用 `pool_workers`；运行时绕过 CLI 传值也会夹到
  `app/limits.py::MAX_CONCURRENCY`，并打印越界截断。
- 模型名单统一交给 `app.gateway.is_serial_model`；命中 `qoder/`、`wb/`、`zcode/`、
  `agy/` 时 workers 强制为 1，并打印命中的模型。
- `run_nat_v2.py` 的第 3 个位置参数经过同一上下界闸；导入模块不再读取 `sys.argv`。
- `ai_ranking_build.py` 保留原请求值 6，但把它作为 `pool_workers` 的请求值，由
  `MAX_CONCURRENCY` 真源夹紧，不再把 6 直接写进 `ThreadPoolExecutor`。
- 默认并发仍为 `source_check=8`、`benchmark_run=6`、`frame_violation=4`、
  `heldout_eval=4`、`overexplain_probe=4`、`pref_judge=4`、
  `prerun_batch_judges=4`、`span_probe=4`、`xcorpus_bias=5`、
  `controlled_corruption=4`、`run_nat_v2=6`、`ai_ranking_build=6`；这些值均不超过 16，
  界内 worker 数和默认路径输出保持原样。

## 1. `_conc_guard.py` 归属与接口

本 worktree 中的 `scripts/_conc_guard.py` 是唯一并发闸实现；12 个脚本只导入它，
没有复制 `check_conc`/`pool_workers` 或串行前缀表。接口为：

```text
check_conc(parser, value, flag="--conc")
pool_workers(conc, models=(), tag="conc", serial_check=is_serial_model)
```

`MIN_CONCURRENCY=1`；上界唯一来源是 `app.limits.MAX_CONCURRENCY`。helper 对 CLI
非法/非整数值、运行时非正值和越界值都显式处理；界内值原样返回且不打印。

`serial_check` 允许各脚本传入自己持有的 `is_serial_model` 绑定，既保持判定口径只有
一处，又使测试可以注入同一判定函数验证没有写死前缀。

**合入说明**：本文件与 `refactor/conc-guard` 任务的 helper 语义一致。合入时只能保留
一份 `_conc_guard.py`，不得把两个分支的文件或实现同时带入；若两条分支都产生该文件，
应由主控二选一后再合入。本批没有修改 `app/`。

### 2.1 单账号模型口径

每个目标脚本把实际模型名单传给共用闸；判定函数来自
`app.gateway.is_serial_model`，没有在脚本中复制 `agy/`、`qoder/`、`wb/`、
`zcode/` 前缀表。`benchmark_run` 和 `controlled_corruption` 原有的串行模型拆分仍保留：
串行模型不进入并行池；其余并行池仍经过上限和串行兜底。
