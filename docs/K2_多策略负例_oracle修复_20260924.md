## 2. 为什么这次「负例身份」是可判的（复审 BLOCK 的对症点）

复审点名的病：旧断言 `"铺陈渲染" in observed_content` **对身份无鉴别力**——
`DEF_B["invariants"]` 里本来就有「不给铺陈渲染」，所以一句完全 B 一致、顺嘴带出
「铺陈渲染」四字的正文（主控用的正是 `...不给铺陈渲染，正是 B 的少动作直给疑问`）
也能满足它。它只核「夹具自己写的字符串被原样透传」，不核归类。

新 oracle 三条要求同时满足才算「这条输入确实是串味」：

1. **名字取自定义本身**：`name_C = 铺陈渲染`、`name_B = 少动作直给疑问`，来自
   `abstract_operation` 冒号前的策略名，而非测试里另写的字面量——改定义即改判据，
   不会与夹具脱钩。
2. **双向断言**：`name_C in observed_content`（正文讲的是 C）**且**
   `name_B not in observed_content`（正文没有讲 B）。单靠「含 C 名」仍可能被
   「B 与 C 都提一句」的正文糊过去，第二半句把这条堵上。
   本组正文 `OC_MATCH` 特意写「不给任何**铺陈**」（不含「渲染」二字），
   即主控实跑那句 `不给铺陈渲染` 会被本 oracle 判为**身份不纯**、用例直接红——
   这正是旧版漏掉、新版拦住的那一类漂移。
3. **单源常量**：① 的正文只有 `OC_CROSS` 一个定义处（170–171 行），②③ 与 xfail
   例共用；想把负例换成正例必须去改模块级常量，而那一改会同时打红
   `test_crossflavor_currently_passes_known_gap`（第 262 行）与 positive_B/合规对照
   一侧，**不可能单边悄悄替换**。

外加**合规对照**（271–275 行）：同一 text、同一 span/evidence、同一 B 定义，
只把正文换成 `OC_MATCH` → 现状同样 `verified`。于是「缺口」被钉成一个**可比较的
命题**（串味与合规不可分），而不是一句注释里的主观描述。日后若实现真能拦串味，
第 275 行的 `r["status"] == r_match["status"] == "verified"` 会红，强制更新本交付。

`xfail strict=True` 那条现在也**先验身份、再宣称缺口**：身份断言在 xfail 例内失败
时结果仍是「失败 → XFAIL」，所以套件不会因此变红；但它的意义在于**与 ② 共用
`OC_CROSS` 单源**——一旦有人把 `OC_CROSS` 换成正例，红的是同文件的非 xfail 用例
（见 §3 M1），xfail 那条不再能孤立地「自说自话」。

## 5. 已知缺口（维持 e4278de 的如实结论，未因本次改动而收窄）

`extract_segment` 的三道门（预算闸 / `gate_output` / `gate_evidence`）只核 span 逐字
与字段完整，**从不比对 `observed_content` 与策略 `abstract_operation` 的语义**，故
「给 B 的定义、正文讲 C」现状照常 `verified`。本次修复只补了**测试侧的负例身份可
判性**（缺口被诚实地、可打红地钉住），**没有**、也不应在 `app/` 里硬造机械判据：
「正文逐字含某不变量短语」测的是「有没有抄我们的措辞」，不是「有没有归对类」，
假阴（正确分类换了话术被误拦）与假阳（照搬短语却仍误归类）同时存在。
真正的修复须落在模型判据或人工复审门；届时 §3 M6 会以「② FAILED + xfail 转 XPASS」
双红强迫移除 xfail 并改写本文件。
