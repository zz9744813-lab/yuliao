## 3. 目标边界与最小闭环

Language Genome 负责语义约束下的表达观察、条件、反例、来源与查询。Novel Distiller 负责叙事机制及证据。Runtime 负责本书场景、状态、提交、恢复与预算。三者不互相写对方的权威业务表。

```text
合格 Human Corpus + 版本化 SemanticFrame
  → Strategy Instance（原文证据留在 LG）
  → 条件化策略版本 + 跨来源统计 + 反例
  → Knowledge Query（按本场语义需要检索）
  → 冻结结果与选择理由
  → Context Compiler（0–3 条抽象操作）
  → 现有 Writer / Verifier / 有限修订 / Commit
  → 使用记录与失败反馈（不自动晋级知识）
```

本阶段不新增复杂 Planner、Dream、Reader Agent 群、世界模型大量新表或训练流水线。现有 ScenePlan 继续作为显式授权；知识只能影响允许范围内的表达，不能新增事件、移动物品、改变资源或改写人物已知信息。

猫神讲解属于“方法主张”，与小说中观察到的表达实例分开登记。同一讲述者的 116 条内容不算 116 个独立来源；先选择与试点场景相符的少量假设，不能把口播结论直接晋级为规则。

## 4. v2 数据契约：保留历史，增加可追溯知识

以下均为**拟建结构**。尽量沿用 LG 的 Work / Segment / Frame 和 Distiller 的证据契约，不新建第二套全文库。

### 4.1 先补来源登记

为既有 Work 增量登记：`canonical_work_id`、已核对的 `author_id`、`genre_ids`、来源类型、文本版本/哈希、用途依据、允许用途、元数据核对状态和依据。字段放在 Work 的扩展表或小型关联表，迁移时不改旧 ID。

- corpus v2、重切段、清洗副本回连同一根作品和内容区间，不计作独立复现。
- `seg_version` 是切分版本，不等同于“属于 corpus v2 镜像”，继续使用现有镜像判定入口。
- fixture / synthetic / commentary / human_fiction 分型，测试材料可以验契约，但不能给人类来源计数加分。
- `src_ok=true` 只证明既定源检查通过，不能替代作者身份、用途、表达质量或阅读效果证明。
- 基准隔离按源身份、文本版本、目标和上下文区间执行；不能只检查 `role` 或完整拼接文本哈希。

### 4.2 五个核心结构

| 结构 | 关键字段及约束 |
|---|---|
| `expression_strategies_v2` | `strategy_id / version`、抽象操作、保持不变项、目标效果假设、失败模式、状态、来源/方法版本；可选 `legacy_strategy_id`。无 `cand_won` 质量门 |
| `strategy_instances` | 策略版本、Work/Segment/Frame 引用、文本版本、span 起止、原文哈希、语义/场景条件、观察内容、效果假设、抽取器/审查版本、proposed/verified/rejected 状态 |
| `strategy_conditions` | `good_when / bad_when / neutral_when`，维度/操作符/值、必需或软条件、证据引用、版本；谓词允许 true/false/unknown |
| `strategy_stats` | 按数据快照生成的统计：唯一源区间、根作品、已知作者、题材、尝试/有效/拒绝/缺失/反例数、集中度与留出复现结果；是可重建投影，不作第二份真值 |
| `knowledge_links` | supports / contradicts / refines / alternative_of 等边，绑定双方 ID、版本、证据与创建依据；可指向 Distiller 机制，不复制机制原文 |

实例证据必须能机械核对 `text_version[span_start:span_end]` 与存证完全相符；Frame 必须属于同一来源版本，缺失时显式为 null，不伪造关联。原文证据留在受控证据层，Writer 只得到抽象操作、条件、例外和不含原文的引用。

重复抽取、不同模型对同一区间的观察、同一段落的多个表达实例分别保留，但统计独立证据时按来源区间/根作品聚合，不能靠重跑增加置信度。语义归纳和效果假设须分别审查，schema 合格不代表推断成立。

### 4.3 覆盖范围、观察支持和效果证据分开

不把附文列出的 `hypothesis → observed → genre_supported → strong_evidence` 当成单一线性等级。三类字段分别记录：

| 维度 | 含义及晋级条件 |
|---|---|
| `scope` | WORK / AUTHOR / GENRE / GLOBAL / UNCERTAIN，必须带具体范围 ID 与依据；不是通用质量排序 |
| `observation_status` | hypothesis：尚无合格实例；observed：有已核对实例；replicated：冻结假设后在独立来源复现，并报告反例/缺失 |
| `effect_status` | untested / pilot_verified / quality_supported；必须绑定具体任务、对照、样本单位和适用条件 |

单部作品只能支持该作品的观察；同作者多部作品仍不能直接支持某题材；多个题材也不自动得到“普遍有效”。本阶段 GLOBAL 只预留契约，不自动授予。缺作者或题材的实例可用于本作品的观察，不可计入对应层次的推广证据。

旧的 Runtime `Technique.evidence_status` 只有 hypothesis / pilot_verified / quality_supported；因此不能直接往旧包塞 observed 等新枚举。新查询和包按版本协商；兼容旧包时保守映射为 hypothesis，并在审计侧保存完整证据层次，绝不把跨语料出现误译成质量通过。

### 4.4 迁移和回滚

新增表与索引先在研究库副本迁移，证明旧 API、旧策略、旧导出读取不受影响；再以有备份、可复核的迁移步骤进入正式库。v1 数据不覆盖、不删除、不静默重解释 `success_rate`。

v1 仅是 legacy 假设来源，默认不作为 v2 已验证查询结果。迁移表须记录旧 ID → 新策略版本及采用依据。错误版本通过 retired / superseded 标记处理；已冻结到历史场景的包保持原样。

## 5. 不依赖 Human Preference 的发现与复现流程

新增 `strategy_discovery_v2`，保留旧脚本及其可复现实验。v2 输入只需合格人类段落、必要上下文和可追溯 Frame，不需要人类/候选胜负标签，也不默认“原文就是好写法”。

1. **登记与抽样**：以 4 部根作品为当前上限，每部最多 12 个合格段，覆盖不同章节、场景功能和表达条件。每部预先分出 8 个开发段、4 个复现段；按章节与重叠区间隔离。缺合格样本就报告缺口，不降低源检查或拿基准凑数。
2. **实例抽取**：每段提出操作、可定位 span、语义不变量、观察与效果假设。先机械验证来源/区间/版本，再进行语义核对；不能由抽取模型自报 confidence 直接晋级。
3. **归纳候选**：从实例聚合可复用操作，首批至多 5 个策略版本。允许一个也不成立；数量不是完成门。
4. **冻结候选**：固定策略定义、条件、检测办法和不适用情况，再打开预留复现段。不能一边看留出答案一边改条件，再称独立验证。
5. **跨来源检查**：逐作品报告试图匹配的段数、合格实例、反例、未知和失败，披露作者/题材集中度；可加留一作品检查，但当前只有 4 部且元数据不齐，结果保持有限外推。
6. **编译与发布**：只有通过来源和条件门的策略进入试点目录。实际写作收益仍待后续 A/B，不由实例计数代替。

发现过程不能读取隐藏基准、其上文或目标文本，也不能让猫神主张、合成负例、真实人类实例共享一个“人类证据数”。模型输出中的指令一律按资料处理，不获得数据库或正史写权限。

## 6. Knowledge Query 与 Runtime 消费契约

### 6.1 接口统一

拟采用 `POST /knowledge/query`，能力说明采用 `GET /knowledge/capabilities`，冻结包采用 `GET /knowledge/packages/{package_id}`。这些接口**现在都没有实现**。长篇总方案 §126 的 `/genome/query` 是旧设计名；实施时统一文档与实现，不新建两套查询服务。

查询首先落在同一 Python 服务层，可由只读本机适配器和 HTTP 薄层共用。验收自动选择行为，不强制先上独立服务、向量数据库或远程部署。

| 输入 | 约束 |
|---|---|
| schema / query policy / knowledge snapshot | 请求与响应可追溯；不认识的版本明确 unsupported |
| book / branch / scene / plan hash | 绑定本场请求；恢复时不悄悄换知识 |
| semantic requirements | 场景功能、表达目标、信息显隐、视角距离、情绪/节奏等结构化需要及 unknown；不把模型猜测当剧情事实 |
| style / negative constraints | 来自作者或冻结计划，优先级高于知识建议 |
| source/split policy | 排除基准、当前评测的留出来源、禁止用途与不合格版本 |
| candidate/context budget | 最多 10 个候选；默认进入正文上下文 0–3 条，另设字符或 token 限额 |

ScenePlan v1 目前只有 goal / style / events 等字段，不能声称已包含完整 Semantic Requirement。第一版用显式输入加有版本的确定性映射，缺失为 unknown；自动语义推断另列实验并记成本。不得修改已提交或已开始调用任务的冻结 ScenePlan。

### 6.2 检索、过滤与排序

首先做来源与版本过滤，再做必需条件、`bad_when` 排除、范围匹配与去重，最后按条件匹配和证据排序。必需条件 unknown 的策略不强行采用；`neutral_when` 不计为正支持。关键词/结构化检索先行，语义向量只有在独立查询集显示收益后再加。

排序须输出可解释分量，不编造“成功率 0.93”。广泛出现只能提高观察支持，不能覆盖本场禁用条件或作者风格。禁止为了达到 5–10 条的数量目标放宽门槛。

响应至少含 `status`、快照/策略版本、选中与拒绝理由、来源引用、scope、观察/效果状态、不确定项、预算消耗及包哈希。`empty`、`unsupported`、`unavailable` 必须区分。

无匹配可以选择明确记录的无知识基线；服务故障是否允许回退由运行配置预先指定，不得隐瞒失败或用旧缓存冒充成功。没有知识不妨碍故事继续，没有权威事实则不能靠知识补造。

### 6.3 从“全书一包”改为“每场冻结一包”

当前 `run_scene.py` 在循环前生成一个 `knowledge-package.json`，三场共用它。新增自动查询不能只替换手填 ID，还必须把查询与冻结移动到**首次 prepare 各场景之前**：

1. 基于该场计划、批准的表达需求和固定知识快照查询。
2. 保存 query、返回候选、拒绝理由、最终 0–3 条选择、编译版本和哈希。
3. Writer 只消费本场冻结包；所有资料仍经过视角和事实权限边界。
4. 同任务恢复读取已冻结输入，不重新检索；知识升级仅影响新任务。相同幂等键但不同输入必须冲突。
5. 旧 CLI 的手选模式和旧试点输入继续可读；自动模式独立显式启用。新包版本不重写既有 3 份收据。

证据 span、参考小说原句、专名和可识别情节不进入 Writer 包。知识不能修改 ScenePlan 的允许事件和状态变化，Critic 也不能因引用知识而自授设定修改权限。模拟分支继续禁止写正史。

## 7. 验证设计：先验证能消费，再判断有没有收益

### 7.1 离线工程验收

- 迁移：旧数据/接口可用；无静默语义重解释，回滚可停用新路径。
- 实例：伪造 span、过期哈希、跨作品 Frame、镜像重复、fixture 冒充 Human、基准上下文泄漏都必须被拦截。
- 查询：建立至少 24 张冻结测试卡，覆盖匹配、bad_when/条件未知、无结果/版本/服务错误三类；硬排除与来源隔离必须全部通过。
- 条件相关性由带证据的人工/独立审查标签核对；开发卡和验收卡分开，不能用实现自己生成的答案键自证语义正确。
- Runtime：每场包冻结、恢复不重查、同键异包拒绝、跨 book / branch 拒绝、预算累计、未知结果不重派；引用和知识条件不能改变正史权限。

工程通过只说明可追溯地选择和消费知识，不说明正文更好。

### 7.2 真实小样本 A/B

先对新接口做无付费夹具验证。相关缺陷门通过后，再在全新实验目录完成一个 **3 场连续原创计划 × 2 个条件** 的真实试点：

| 对照 A | 实验 B | 固定因素 |
|---|---|---|
| 明确的空知识包 | 根据本场需求自动查询，允许返回空 | 初始世界、三场事件/允许变化、Writer/Verifier 模型及实际路由、提示词、预算、长度要求和其余生成参数 |

两组各有独立实验 DB 和作品标识，各自顺序延续状态；它们的本地提交不进入用户已有作品正史，也不共用原试点输出目录。不能通过解除 simulation 禁写来实现对照。

原“灯下渡口”三场可用于兼容回归，不作为新的独立效果证据。质量试点使用提前冻结的新计划；若接口调试已经看过该计划，则标为开发样例并另留验收样例。

逐场记录：

1. 所选知识是否适用、哪些没采用、为何没采用；Writer 的自述不当作采用证据，需定位最终文本中的可观察变化。
2. 事实/角色知识错误、未授权变化、事件完成率、跨场资源和承诺连续性。
3. Writer 修稿次数、Verifier 工件返修次数、人工介入和完整请求尝试/用量；两类返修分别计数，共用总调用上限。
4. 配对的可读性/表达目标评审，保留引文和反例；匿名化条件与顺序，评审不看知识包和写作者自评。原始模型判断、操作者复核与用户反馈分别记录，不伪造人类票。
5. 总输入/输出 token、失败/未知、请求耗时、知识查询开销和缺失账单。

三场属于一个连续故事，不按 3 个独立实验做显著性推断。阶段通过条件是链路真实可用、状态和账本可核验、所有确认硬问题清零；即使全部成立，也最多记 `pilot_verified`。若知识没有可观察收益，保留负结果或禁用对应策略，不能事后换指标宣布成功。

### 7.3 预算与停止条件

以下是**下一阶段拟定上限**，本轮写方案没有发起真实模型请求：

| 环节 | 上限与停止规则 |
|---|---|
| 来源/知识试点 | 最多 48 段；每段至多 1 次抽取 + 1 次契约修复，全部派发合计最多 96 次；探针也占总额。每次输入最多 16,000 字符、输出最多 2,000 token；达到任一上限保留未完成项 |
| 查询 | 优先确定性实现，0 次模型调用；若需要模型推断需求，另建预算，不挤入“免费检索” |
| Writer A/B | 2 组 × 3 场 × 每场最多 6 次调用 = 最多 36 次；每场最多 2 次正文修订，核验修复也占 6 次总额；默认沿用 24,000 输入字符、3,000 输出 token/次、累计请求耗时 600 秒/场 |
| bal-v2 收尾 | 只处理现有版本、已有模型面板和当前尝试；记录已花与剩余额度。若恢复需要重新发送未知请求，不自动补跑 |
| 金额 | 单价/账单缺失时费用为 null；调用/token 上限不冒称人民币硬上限。待有可靠价表才增加货币预算闸门 |

重启、重试、返回截断、契约修复、上游 unknown 均不能重置预算；达到上限即停并落盘。未知结果先对账，不自动重派；无收益、证据不够或实验失败都可正常结束本批次，不以“必须做出正结果”为停止条件。
